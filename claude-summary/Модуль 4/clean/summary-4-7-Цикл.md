# Цикл

## О чём этот урок

Урок посвящён использованию действия **«Цикл»** в конструкторе бизнес-процессов Bitrix24. На практике разбирается задача: если руководитель отклоняет заявку, она должна возвращаться сотруднику на доработку — и так повторяться до тех пор, пока заявка не будет одобрена. Ключевая идея — правильно определить условие выхода из цикла через переменную «Внутренний статус».

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Цикл** | Действие в конструкторе бизнес-процессов, которое повторяет набор вложенных поддействий до тех пор, пока выполняется заданное условие |
| **Условие выхода из цикла** | Логическое условие, при нарушении которого цикл прекращает выполняться и передаёт управление следующему блоку |
| **Переменная «Внутренний статус»** | Переменная типа «да/нет», которая управляет поведением цикла: пока значение `Нет` — цикл продолжается, как только становится `Да` — цикл завершается |
| **Поддействия цикла** | Набор блоков внутри цикла, которые выполняются на каждой итерации |
| **Обособленный блок утверждения** | Логически выделенная часть процесса («утверждение заявки руководителем»), которую удобно помещать в цикл как единицу |
| **Максимальное число итераций** | Ограничение, защищающее от бесконечного цикла; рекомендуется устанавливать всегда |

---

## Проблема, которую решает цикл

До введения цикла схема процесса выглядела так:

```
Заявка → Условие (одобрено / отклонено) → ...дальнейшие блоки...
```

**Проблема:** При отклонении заявки руководителем процесс всё равно шёл дальше — на проверку суммы сделки и согласование с бухгалтером. Это логически неверно: до этих блоков нужно доходить **только при одобрении**.

**Цель:** Если руководитель отклонил — вернуть заявку на доработку и снова отправить на утверждение. Повторять до тех пор, пока не будет получено одобрение.

---

## Архитектурное решение: почему важно обособить блок утверждения

Перед тем как добавить цикл, необходимо принять важное архитектурное решение:

> «Я утверждение заявки хочу видеть как отдельный небольшой блок, чтобы можно было спокойно его поместить в цикл»

**Почему нельзя брать всё подряд в цикл:**
- Визуально схема становится нечитаемой
- Тащить в цикл всю большую цепочку (проверка суммы → бухгалтер) — некорректно по логике
- Увеличивается риск ошибок в условиях выхода

**Правило:** В цикл помещается **только тот набор действий, который должен повторяться**. В данном случае — только блок «утверждение у руководителя».

---

## Структура цикла

```
[Начало цикла] — условие продолжения
  │
  ├─ Задание: согласование у руководителя
  ├─ Условие: одобрено?
  │    ├─ Да → выход из цикла
  │    └─ Нет → запрос доработки у сотрудника
  │         └─ Условие: сотрудник хочет дорабатывать?
  │              ├─ Да → возврат в начало цикла
  │              └─ Нет → выход (заявка закрыта)
  │
[Конец цикла]
```

---

## Как работает цикл: механика

```
Установка переменной: Внутренний статус = Нет
           ↓
┌──────────────────────────────────────────────┐
│  ЦИКЛ (пока Внутренний статус = Нет)         │
│                                              │
│  → Руководитель утверждает заявку            │
│  → Если одобрено:                            │
│       Установить Внутренний статус = Да      │
│  → Если отклонено:                           │
│       (статус остаётся Нет)                  │
│       → следующая итерация                   │
└──────────────────────────────────────────────┘
           ↓ (выход из цикла, когда статус = Да)
Проверка суммы → Согласование с бухгалтером → ...
```

**Ключевой момент:** Условие цикла — «пока значение переменной `Внутренний статус` равно `Нет`». Как только переменная становится `Да` — условие нарушается и цикл завершается.

---

## Пошаговая инструкция: добавление цикла в бизнес-процесс

### Шаг 1 — Обособить блок утверждения

Переструктурировать схему так, чтобы блок «утверждение у руководителя» был логически отдельным, компактным фрагментом — только ту логику, которая должна повторяться.

---

### Шаг 2 — Добавить действие «Цикл»

В конструкторе бизнес-процессов добавить действие **«Цикл»** в нужное место схемы.

---

### Шаг 3 — Настроить условие выхода из цикла

Открыть настройки действия «Цикл» и задать условие:

```
Переменная [Внутренний статус] = Нет
```

> Читается так: «Цикл выполняет свои поддействия до тех пор, пока выполняется заданное условие» — то есть пока `Внутренний статус = Нет`.

Дополнительно: задать **максимальное число итераций** — защита от бесконечного цикла.

---

### Шаг 4 — Установить начальное значение переменной

**До цикла** добавить блок «Установка значения переменной»:

```
Внутренний статус ← Нет
```

> Это гарантирует, что при каждом новом запуске цикл начнёт работу корректно. Если поставить этот блок **внутри** цикла — каждая итерация будет сбрасывать значение, и выход из цикла станет невозможным.

---

### Шаг 5 — Поместить поддействия внутрь цикла

Внутрь цикла перенести:
- Блок **«Руководитель утверждает заявку»** (задание на одобрение / отклонение)

---

### Шаг 6 — Установить значение переменной при одобрении

Внутри цикла, в ветке **«Одобрено»**, добавить блок «Установка значения переменной»:

```
Внутренний статус ← Да
```

**Итог логики:**
- Руководитель **одобряет** → переменная становится `Да` → условие цикла нарушается → цикл завершается → выполнение идёт дальше
- Руководитель **отклоняет** → переменная остаётся `Нет` → цикл запускает следующую итерацию

---

## На что обратить внимание

- **Порядок блоков важен:** установка `Внутренний статус = Нет` должна быть **до** цикла, а не внутри — иначе каждая итерация будет сбрасывать значение
- **Условие цикла — «пока выполняется»**, а не «пока не выполняется»; нужно чётко понимать формулировку: цикл работает, **пока** условие `= Нет` истинно
- **Блоки после цикла** (сумма сделки, бухгалтер) выполняются только после выхода из цикла — то есть только при одобрении руководителя
- **Визуальная читаемость:** не стоит помещать в цикл слишком большие фрагменты схемы — это усложняет понимание и увеличивает риск логических ошибок
- **Максимальное число итераций** рекомендуется устанавливать всегда — защита от зависшего процесса

---

## Главное

1. **Цикл** — инструмент для повторения набора действий при невыполнении условия выхода; применяется там, где действие должно повторяться до получения нужного результата.
2. **Переменная — основа управления циклом:** именно через изменение значения переменной (`Нет` → `Да`) организуется выход из цикла.
3. **Перед использованием цикла — обособить повторяемый блок:** в цикл помещается только та логика, которая должна повторяться; остальное — за его пределами.
4. **Начальное значение переменной устанавливается строго до цикла** — это обязательный шаг, иначе поведение непредсказуемо или цикл не завершится никогда.
5. **Условие цикла читается как «продолжать, пока...»** — нужно формулировать его точно, не путать «пока выполняется» и «пока не выполняется».
6. **Архитектура важнее скорости:** прежде чем добавлять цикл, стоит остановиться и подумать о структуре — что именно должно повторяться, а что выполняться однократно после.
7. **Блоки за пределами цикла выполняются только при выходе из него** — это позволяет чётко разделить логику «в процессе согласования» и «согласование завершено».
8. **Максимальное число итераций** — обязательный параметр безопасности; предотвращает зависание бизнес-процесса при непредвиденных ситуациях.
