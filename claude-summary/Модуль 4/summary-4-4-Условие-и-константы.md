# Модуль 4, Урок 8 — Условие и константы в бизнес-процессе Bitrix24

## О чём этот урок

Урок посвящён усложнению схемы бизнес-процесса: добавлению блока согласования у бухгалтера с использованием действия **«Условие»** и нового типа параметров — **констант**. На практике разбирается, как разветвить логику процесса в зависимости от суммы заявки и как правильно хранить «фиксированных» участников процесса.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Условие** | Действие в бизнес-процессе, которое проверяет заданные критерии и направляет выполнение по одной из нескольких веток |
| **Ветка условия** | Отдельный путь выполнения бизнес-процесса, по которому процесс идёт при выполнении соответствующего критерия |
| **Константа** | Параметр шаблона бизнес-процесса с фиксированным значением, которое задаётся один раз и используется повторно во всех запускаемых экземплярах процесса |
| **Переменная** | Параметр процесса, значение которого меняется в ходе выполнения (в отличие от константы) |
| **Динамическое определение** | Способ задания участника процесса «на лету» — например, руководитель определяется по автору заявки |
| **Согласование у бухгалтера** | Дополнительный этап утверждения заявки, подключаемый при выполнении условия (сумма > 15 000 ₽) |

---

## Логика расширенной схемы бизнес-процесса

### Общая структура после добавления условия

```
[Утверждение у руководителя]
          ↓
     [Условие]
    /          \
(сумма > 15 000)  (иначе — всегда True)
       ↓                   ↓
[Согласование        [Завершение /
 у бухгалтера]        следующий шаг]
```

### Где ставится условие

Блок **«Условие»** добавляется **после** того, как руководитель одобрил заявку. То есть согласование у бухгалтера — это не параллельный, а **последовательный** этап, который подключается только при необходимости.

---

## Действие «Условие» — детальный разбор

### Ключевые особенности

1. **Несколько веток** — условие позволяет создавать не только 2, но и 3, 4 и более путей выполнения.
2. **Проверка слева направо** — ветки проверяются строго по порядку, от левой к правой. Это критически важно при проектировании логики.
3. **Обязательная «страховочная» ветка** — классическая практика: **правая ветка всегда содержит условие «Истина»** (всегда выполняется), чтобы бизнес-процесс гарантированно прошёл через условие и не завис.

### Правило проектирования условий (классика жанра)

```
Левая ветка  →  конкретное условие (например, сумма > 15 000)
Правая ветка →  Истина (всегда True — «иначе»)
```

> Это гарантирует, что хотя бы одна ветка сработает при любых данных.

### Настройка условия для согласования с бухгалтером

- **Критерий:** поле «Сумма» заявки > 15 000 рублей
- **Левая ветка (условие выполнено):** переходим к блоку согласования у бухгалтера
- **Правая ветка (условие не выполнено / иначе):** пропускаем бухгалтера, идём дальше

## Константы — зачем и когда использовать

### Проблема: бухгалтер vs руководитель

| Участник | Как определяется | Инструмент |
|---|---|---|
| Руководитель | Динамически — по автору заявки (у каждого сотрудника свой руководитель) | **Переменная** |
| Бухгалтер (главбух) | Статически — один конкретный человек для всей компании | **Константа** |

### Преимущества константы

- Значение задаётся **один раз** в настройках шаблона
- Используется **во всех запускаемых экземплярах** процесса автоматически
- При смене главбуха достаточно **изменить константу один раз** — все будущие запуски подхватят новое значение
- Не нужно вручную прописывать конкретного пользователя в каждое действие

### Альтернативный (неудобный) способ

Можно было бы: войти в организационную структуру → найти бухгалтерию → выбрать главного бухгалтера → указать его напрямую в настройке действия. Но это жёсткая привязка — при смене сотрудника придётся редактировать каждое действие вручную.

## Пошаговые инструкции

### Шаг 1. Добавить блок «Условие» в схему

1. Открыть редактор бизнес-процесса.
2. Найти место после блока «Утверждение у руководителя».
3. Добавить действие **«Условие»** между блоком руководителя и следующим шагом.
4. Убедиться, что условие стоит именно **после одобрения руководителя** (не параллельно).

### Шаг 2. Настроить ветки условия

1. В блоке «Условие» настроить **левую ветку**:
   - Поле: `Сумма`
   - Оператор: `больше`
   - Значение: `15000`
2. В **правой ветке** установить условие **«Истина»** (всегда выполняется).
3. Сохранить настройки условия.

### Шаг 3. Создать константу для бухгалтера

1. Перейти в **«Параметры шаблона»**.
2. Открыть раздел **«Константы»**.
3. Нажать **«Добавить константу»**.
4. Задать имя константы (например, `Главный бухгалтер`).
5. Выбрать значение — конкретный пользователь (главный бухгалтер) из списка сотрудников.
6. Сохранить константу.

### Шаг 4. Использовать константу в блоке согласования

1. Добавить блок **«Задание»** (согласование) в левую ветку условия.
2. В поле «Исполнитель» / «Кому направить» выбрать не пользователя напрямую, а созданную **константу**.
3. Настроить варианты ответа: **Утвердить / Отклонить**.
4. Добавить уведомления пользователям по результату.
5. Сохранить.

---

## На что обратить особое внимание

> **Порядок веток в условии имеет значение.** Если поставить «Истина» слева — она сработает первой и процесс никогда не дойдёт до правой ветки с реальным условием. Всегда: конкретное условие — слева, «Истина» — справа.

> **Константа ≠ Переменная.** Константа не меняется в ходе выполнения процесса — это фиксированный параметр шаблона. Переменная может принимать разные значения в зависимости от хода процесса.

> **Согласование у бухгалтера — это дополнительный уровень.** Если бухгалтер отклонил заявку, решение руководителя теряет силу.

---

## Главное

1. **Действие «Условие»** позволяет создавать разветвлённую логику с любым количеством веток — не только два пути.
2. **Порядок проверки — слева направо**: первой всегда проверяется левая ветка.
3. **Правая ветка = «Истина»** — обязательный паттерн, страхующий процесс от зависания на условии.
4. **Константа** — инструмент для участников процесса с заранее известным, фиксированным значением (например, единственный главбух).
5. **Переменная** — для участников, определяемых динамически в момент запуска (например, руководитель автора заявки).
6. **Смена константы один раз** автоматически распространяется на все будущие запуски процесса — это удобнее, чем менять каждое действие вручную.
7. **Бухгалтер подключается только при сумме > 15 000 ₽** — пример условной маршрутизации в реальном бизнес-сценарии.
8. **Согласование у бухгалтера по структуре аналогично согласованию у руководителя**, но с одним отличием: исполнитель определяется через константу, а не динамически.
9. **После настройки условия** необходимо также добавить уведомления пользователям по итогам работы бухгалтерского согласования.
