# Модуль 3, Урок 6: Калькулятор и Модификаторы

## О чём этот урок

Урок посвящён двум мощным инструментам дизайнера бизнес-процессов: **Калькулятору** — встроенному вычислительному движку, позволяющему выполнять арифметику, работать с датами и применять формулы прямо внутри полей действий — и **Модификаторам** — механизму преобразования типов и форматов данных при вставке значений. Без этих инструментов невозможно строить реальные, нетривиальные бизнес-процессы: почти всегда нужно не просто «взять значение», а что-то вычислить или преобразовать.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Калькулятор** | Встроенный в дизайнер БП вычислительный движок, позволяющий вычислять значения прямо внутри полей параметров действий |
| **Синтаксис `=`** | Запись выражения начиная со знака `=` в поле параметра — сигнал системе, что это вычисляемое значение, а не текст |
| **Двойные фигурные скобки `{{= }}`** | Конструкция для вставки вычисляемого выражения **внутри текстовой строки**; позволяет смешивать статический текст и вычисления |
| **Одинарные фигурные скобки `{ }`** | Синтаксис подстановки значения из переменных/полей документа (генерируется формой «Вставка значений») |
| **Модификаторы** | Специальные преобразования, применяемые к вставляемому значению: меняют тип данных или формат отображения |
| **`addworkdays()`** | Встроенная функция калькулятора — добавляет N **рабочих дней** к указанной дате (пропускает выходные) |
| **Действие «Остановить процесс»** | Служебное действие, прерывающее выполнение БП; используется при отладке, чтобы изолировать тестируемое действие |
| **Запуск при изменении** | Режим запуска шаблона БП, при котором процесс перезапускается каждый раз при изменении документа — удобен для многократного тестирования |

## Как работает Калькулятор

### Базовый принцип

Калькулятор — это **не отдельное действие**. Это встроенная возможность **любого поля** параметров действий. Если в поле параметра ввести значение, начинающееся со знака `=`, система интерпретирует содержимое поля как **формулу** и вычислит результат перед выполнением действия.

> «Фактически система сейчас нам будет вычислять эти значения. То есть не текст нам напишет равно 2 плюс 2, а вычислит 4 и отправит в виде сообщения.»

### Три синтаксиса для работы с вычислениями

#### 1. Полное поле — только формула
```
=2+2
```
- Всё поле параметра является формулой
- Результат: `4`
- Применяется, когда поле должно содержать **только** вычисленное значение

#### 2. Формула внутри текста — двойные скобки
```
Вам сообщение: {{=2+2}}
```
- Часть текста — статическая, часть — вычисляемая
- Результат: `Вам сообщение: 4`
- Применяется, когда нужно сформировать **текстовое сообщение** с вычисленными вставками

#### 3. Формула с полями документа
```
2 + ID элемента: {{=2+{Document:ID}}}
```
- Внутри `{{= }}` используется обычная подстановка `{Document:ID}` — значение из поля документа
- Результат при ID=5: `2 + ID элемента: 7`
- Позволяет **комбинировать переменные БП с арифметикой**

> Важно: одинарные фигурные скобки `{Document:ID}` — это синтаксис подстановки, генерируемый формой «Вставка значений». Двойные `{{= }}` — это синтаксис калькулятора, оборачивающий формулу.

## Практический пример из урока: вычисление даты дедлайна

### Задача
После того как руководитель одобрил отпуск — автоматически создать задачу сотруднику на передачу дел. **Дедлайн задачи** = текущая дата + 2 рабочих дня.

Нельзя просто взять поле даты из документа — нужно именно **вычислить**: прибавить к текущей дате два рабочих дня (не календарных).

### Решение: функция `addworkdays()`

```
addworkdays(текущая дата, 2)
```

Функция принимает два аргумента:
1. **Базовая дата** — переменная «Текущая дата» (берётся из формы вставки значений)
2. **Количество рабочих дней** для добавления

### Как это выглядит в формуле
```
{{=addworkdays({=system:Now}, 2)}}
```
или через вставку из интерфейса — переменная «Текущая дата» + функция `addworkdays`.

### Проверка корректности
Тест из урока:
- Сегодня **суббота, 19-е** (выходной)
- Воскресенье, 20-е — тоже выходной
- Понедельник, 21-е — 1-й рабочий день
- Вторник, 22-е — 2-й рабочий день
- Результат: **22.01** ✓ — функция корректно пропустила выходные

## Возможности Калькулятора (полный обзор)

### Интерфейс при вводе `=`
При вводе знака `=` в поле параметра появляется **специальная форма** с доступными элементами:

| Категория | Что входит |
|---|---|
| **Переменные** | Параметры шаблона, переменные, константы |
| **Поля документа** | Все поля объекта, по которому запущен БП |
| **Дополнительные результаты** | Результаты выполненных ранее действий |
| **Константы** | Заданные разработчиком постоянные значения |
| **Системные переменные** | Время сервера, локальное время, текущая дата |
| **Функции** | Большой набор встроенных функций (см. ниже) |

### Категории доступных операций

#### Математические операции
- Сложение, вычитание, умножение, деление
- Возведение в степень, остаток от деления
- Любые арифметические выражения

#### Операции сравнения
- `>`, `<`, `>=`, `<=`, `=`, `!=`
- Результат — логическое значение (истина/ложь)

#### Логические операции
- `AND`, `OR`, `NOT`
- Построение составных условий

#### Математические функции
- Округление, абсолютное значение, корень и т.д.

#### Функции для работы с датами

- Форматировать дату в строку
- Получить отдельные компоненты даты (день, месяц, год)

#### Условные выражения (IF)
- Аналог тернарного оператора: `IF(условие, значение_если_да, значение_если_нет)`

#### Работа с массивами

## Модификаторы

### Зачем нужны

Модификаторы решают проблему **несовместимости типов** при вставке значений. Например:
- Нужно вывести дату в определённом текстовом формате
- Нужно преобразовать строку в число для арифметики
- Нужно изменить регистр текста
- Нужно взять только часть значения

### Как применяются

Модификатор добавляется к синтаксису подстановки значения, указывая системе: «возьми это значение, но преобразуй его вот так перед подстановкой».

## Техника отладки при работе с Калькулятором

### Приём «изолировать действие»

При эксперименте с формулой удобно не запускать весь бизнес-процесс целиком. Используется следующий приём:

1. После тестируемого действия (например, «Сообщение») вставить действие **«Остановить процесс»**
2. БП выполнит только первое действие и остановится — остальные шаги не пройдут
3. Можно быстро проверять результаты без «шума» от остальных действий

### Режим «Запуск при изменении»

- Настройка шаблона: **запуск при изменении документа**
- Позволяет многократно перезапускать БП, просто открыв документ и нажав «Применить»
- Не нужно каждый раз создавать новый документ — один и тот же можно изменять снова и снова

### Алгоритм быстрого тестирования

```
1. Настроить шаблон на «Запуск при изменении»
2. Вставить тестируемое действие (например, «Сообщение» с формулой)
3. Вставить «Остановить процесс» сразу после
4. Сохранить шаблон
5. Открыть тестовый документ → Применить
6. Проверить результат в уведомлениях
7. Скорректировать формулу → Сохранить → повторить
```

## Пошаговые инструкции

### Ввести простую формулу в поле параметра действия

1. Открыть параметры нужного действия в дизайнере
2. Нажать в нужное поле параметра
3. Ввести `=` — появится форма с доступными переменными и функциями
4. Скрыть форму (если мешает) и вписать формулу вручную, например `=2+2`
5. Сохранить параметры

> При вводе `=` система активирует режим вычисления — поле будет не текстовым, а формульным.

---

### Вставить вычисление внутри текстового сообщения

1. Открыть параметры действия «Сообщение»
2. В поле текста сообщения написать, например: `Вам сообщение: {{=2+2}}`
3. Конструкция `{{= }}` — это контейнер для формулы внутри текстовой строки
4. Внутри `{{= }}` можно использовать те же формулы и функции, что и в полном режиме

---

### Использовать поле документа в формуле

1. Написать начало формулы: `{{=2+`
2. Открыть форму вставки значений (кнопка рядом с полем) — или вставить через `=` форму
3. Выбрать нужное поле документа, например «ID элемента»
4. Система вставит синтаксис: `{Document:ID}`
5. Закрыть скобку: `{{=2+{Document:ID}}}`
6. Результат: при выполнении БП значение ID будет подставлено и посчитано

---

### Вычислить дату через N рабочих дней

1. Открыть параметры действия, поле типа «Дата» (например, «Крайний срок» у задачи)
2. Активировать режим калькулятора, введя `=`
3. Найти в документации функцию `addworkdays`: принимает (дата, N)
4. Составить формулу: `addworkdays({=system:Now}, 2)` — или через форму выбрать «Текущая дата» и обернуть в функцию
5. Сохранить — при выполнении БП автоматически прибавит 2 рабочих дня к текущей дате

## Главное

1. **Калькулятор — это не отдельное действие, а встроенная возможность любого поля.** Знак `=` в начале значения — переключатель в режим формулы.

2. **Два синтаксиса для двух задач:**
   - `=формула` — когда всё поле является вычислением
   - `{{=формула}}` — когда нужно вставить вычисление **внутри текста**

3. **Поля документа и переменные можно использовать прямо внутри формул.** Синтаксис `{Document:FIELD}` работает внутри `{{= }}` — это даёт возможность вычислять на основе реальных данных.

4. **`addworkdays()` — ключевая функция для бизнес-задач с датами.** Добавляет именно рабочие дни, пропуская выходные — это стандартная потребность при постановке сроков.

5. **Полная документация по калькулятору (helpdesk.bitrix24.ru/open/5428897/) — must read.** Там математика, даты, логика, условия, массивы. Эту страницу разработчики БП используют постоянно.

6. **Модификаторы нужны, когда тип данных не совпадает с нужным форматом.** Прежде чем «изобретать велосипед», проверь: возможно, нужный модификатор уже есть в таблице.

7. **Действие «Остановить процесс» — инструмент отладки.** Вставь его после тестируемого действия — и БП не пойдёт дальше, пока ты не разберёшься с формулой.

8. **Режим «Запуск при изменении» + «Остановить процесс» = быстрый цикл тестирования.** Изменил → Применил → Проверил уведомление → Скорректировал. Без создания новых документов.

9. **Начинать стоит с простого: `=2+2`.** Убедись, что принцип работает, потом усложняй. Это снижает риск путаться в синтаксисе при первом знакомстве.

10. **Калькулятор + вставка значений = полноценный язык выражений внутри БП.** Вместе они позволяют строить логику вычислений прямо в параметрах действий, без отдельных «вычислительных» блоков.
