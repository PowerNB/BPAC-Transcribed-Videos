# Модуль 3: Автоматизация бизнес-процессов в Bitrix24 — Итоговый обзорный конспект

## О модуле

Модуль посвящён практической работе с бизнес-процессами (БП) в Bitrix24: от безопасного управления шаблонами до построения сложной автоматизированной логики. Центральный инструмент модуля — **Дизайнер БП**, визуальный редактор, в котором из блоков-действий собирается любой процесс. Модуль последовательно формирует три уровня компетенций: управление шаблонами → конструирование процессов → динамическое наполнение данными. Каждая тема является фундаментом для следующей: без понимания структуры дизайнера невозможно грамотно настраивать параметры, а без параметров — применять калькулятор и модификаторы.

---

## Смысловой блок 1: Безопасная работа с шаблонами

### Архитектура: шаблон vs запущенный процесс

Понимание этого различия — обязательная основа для всей дальнейшей работы:

```
Шаблон БП (чертёж)  →  момент запуска  →  Запущенный БП (живой экземпляр)
        ↑                                           ↓
  Можно редактировать                  Работает по зафиксированному маршруту
  в любой момент                       Изменения шаблона его НЕ затрагивают
```

- **Шаблон** — описание процесса. Редактируется свободно в любое время.
- **Запущенный БП** — в момент старта копирует весь маршрут из шаблона и далее работает независимо.
- Изменения шаблона влияют только на **новые** запуски — уже идущие процессы продолжают работать по старому маршруту.

> **Практический вывод:** можно смело дорабатывать шаблон, не прерывая текущих процессов.

### Копирование шаблона через экспорт/импорт

Перед любым изменением типового или рабочего шаблона — создать копию. Механизм: **экспорт оригинала → создание пустого шаблона → импорт файла в него**.

| Зачем | Как |
|---|---|
| Безопасно изучать и изменять | Все эксперименты — только в копии |
| Откатиться к исходному состоянию | Оригинал нетронут |
| Перенести шаблон между порталами | Экспорт → файл `.bpt` → Импорт на другом портале |
| Тиражировать типовое решение | Тот же механизм, другой портал |

> **Золотое правило:** всегда создавай копию перед изменением любого рабочего шаблона.

## Смысловой блок 2: Структура и инструментарий Дизайнера

### Визуальный редактор и структура шаблона

**Дизайнер** — визуальный редактор шаблонов. Шаблон строится из **действий** (блоков), расположенных в рабочей области. Справа — панель с категориями действий.

Визуальные элементы шаблона:
- **Последовательность** — линейная цепочка шагов
- **Ветвления (условия)** — развилки с несколькими путями
- **Циклы** — повторяющиеся блоки, обведённые замкнутыми линиями

### Категории действий — сводная карта

| Категория | Ключевые возможности | Документация |
|---|---|---|
| **Обработка документа** | Изменение полей объекта; запуск другого БП по любому объекту системы | helpdesk.bitrix24.ru/open/7449433 |
| **Задания** | Интерактив с пользователем: согласование, утверждение, решение | helpdesk.bitrix24.ru/open/7451037 |

### Ключевые различия, которые часто путают

| Задания | Уведомления |
|---|---|
| Двусторонний диалог | Одностороннее информирование |
| Процесс **ждёт** ответа пользователя | Процесс продолжается сразу |
| «Согласуйте», «Утвердите» | «Вам сообщение», «Уведомляем» |

### Мощные возможности для цепочек автоматизации

- **«Запуск БП»** (в блоке «Обработка документа») — один процесс может запустить другой по **любому объекту системы**
- **Веб-хук** — мгновенная интеграция с внешними системами без написания серверного кода: HTTP-запрос с данными в любой URL
- **Кастомные действия** через приложения — расширение стандартного набора, доступно в облаке

## Смысловой блок 3: Динамические данные в параметрах действий

### Форма «Вставка значений» — 7 блоков

Каждое действие имеет параметры. Вместо статичных значений — **динамические**, подставляемые в момент выполнения:

| Блок | Что даёт |
|---|---|
| **Параметры шаблона** | Значения, заданные разработчиком на уровне шаблона |
| **Переменные** | Промежуточные данные внутри процесса |
| **Константы** | Постоянные значения, не меняющиеся в ходе БП |
| **Поля документа** | Поля объекта, по которому запущен БП |
| **Дополнительные результаты** | Результаты предыдущих действий — мост между блоками |
| **Пользователи** | Конкретный сотрудник |
| **Категория пользователей** | Отдел, группа, роль |

> **Ключевое поведение:** форма автоматически фильтрует значения по **совместимому типу** — нельзя вставить дату туда, где ожидается пользователь.

**Синтаксис подстановки:**
```
{=Document:FIELD_CODE}    — значение из поля документа
```

### Параметр «Остановить процесс на время задачи»

Специальный параметр действия «Задача»:
- **Да** → БП приостанавливается и ждёт закрытия задачи (создаёт обязательный шлюз)
- **Нет** → БП идёт дальше, не ожидая

## Смысловой блок 4: Вычисление значений — Калькулятор

Калькулятор — **не отдельное действие**, а встроенный режим **любого поля** параметра. Знак `=` в начале значения активирует формульный режим.

### Три синтаксиса

| Задача | Синтаксис | Пример |
|---|---|---|
| Всё поле — формула | `=формула` | `=2+2` → `4` |
| Формула внутри текста | `{{=формула}}` | `Сумма: {{=2+2}}` → `Сумма: 4` |
| Поле документа в формуле | `{{=функция({Document:FIELD})}}` | `{{=addworkdays({=system:Now}, 2)}}` |

### Категории операций

- **Математические:** `+`, `-`, `*`, `/`, степень, остаток
- **Сравнение:** `>`, `<`, `>=`, `<=`, `=`, `!=`
- **Логические:** `AND`, `OR`, `NOT`
- **Условные:** `IF(условие, если_да, если_нет)`
- **Функции дат:** `addworkdays(дата, N)` — прибавляет рабочие дни, пропуская выходные
- **Работа с массивами, строками**

> **Ключевая функция для бизнес-задач:** `addworkdays(дата, N)` — стандартная потребность при постановке дедлайнов.

### Системные переменные

Доступны прямо в формулах: `{=system:Now}` — текущая дата/время сервера.

## Смысловой блок 5: Форматирование данных — Модификаторы

### Проблема, которую решают модификаторы

Многие поля Bitrix24 хранят **системные идентификаторы**, а не читаемый текст:

```
Поле «Кем создан» без модификатора:  42
Поле «Кем создан» с printable:       Иван Иванов
```

Без модификаторов уведомления выглядят как системный лог — неприемлемо в production-среде.

### Модификатор vs Калькулятор

| Инструмент | Задача |
|---|---|
| **Модификатор** | Меняет **формат/тип** существующего значения |
| **Калькулятор** | **Вычисляет** новое значение |

В сложных формулах оба работают совместно.

### Синтаксис

```
Без модификатора:   {Document:FIELD}
С модификатором:    {Document:FIELD|printable}
```

### Категории модификаторов

| Группа | Применение |
|---|---|
| **`printable`** | Главный модификатор: ID → читаемое имя/название |
| **Преобразование типов** | Число → строка, дата → строка и т.д. (для корректных сравнений) |
| **Форматирование** | Формат даты, знаки после запятой |
| **Работа с текстом** | Регистр, обрезка, замена символов |

> **Правило:** видишь число там, где должно быть имя — ставь `printable`.

**Документация:** helpdesk.bitrix24.ru/open/5426411/

## Смысловой блок 6: Отладка и хорошие практики

### Инструменты быстрого тестирования

| Приём | Суть |
|---|---|
| **«Прерывание процесса»** | Останавливает БП после нужной точки — тестируем только один шаг |
| **Режим «Запуск при изменении»** | Перезапускаем БП, просто открыв документ и нажав «Применить» |
| **Два значения рядом** | Вставить поле без модификатора и с `printable` — наглядное сравнение |

### Быстрый цикл тестирования

```
Настроить → Сохранить → Открыть документ → Применить → Проверить → Скорректировать → повторить
```

### Именование действий

Давайте действиям **понятные, описательные названия**. Это критично для:
- Поддержки и доработки шаблонов через время
- Командной работы
- Отладки сложных шаблонов

### Добавление действий: контекстное меню vs перетаскивание

**Рекомендуется:** нажать на стрелку-связь между действиями → выбрать из контекстного меню. Позволяет точно позиционировать действие без промахов.

## Связи между темами модуля

```
Видео 1: Копирование шаблонов
    └── Фундамент: без копий нельзя безопасно экспериментировать
          ↓
Видео 2: Дизайнер и действия
    └── Карта инструментов: что вообще можно сделать в БП
          ↓
Видео 3: Параметры и вставка значений
    └── Как наполнить действия данными из документа и других блоков
          ↓
Видео 4: Калькулятор
    └── Как вычислять значения, если их нельзя взять напрямую
          ↓
Видео 5: Модификаторы
    └── Как форматировать значения для корректного отображения и сравнения
```

## Ключевые выводы модуля

1. **Шаблон ≠ запущенный процесс.** Шаблон — чертёж; запущенный БП — независимый экземпляр, зафиксировавший маршрут в момент старта. Изменения шаблона влияют только на новые запуски.
2. **Копия шаблона — обязательный шаг** перед любым изменением рабочего процесса. Механизм: экспорт → создание пустого шаблона → импорт. Применяется также для резервных копий и переноса между порталами.
3. **Дизайнер — визуальный конструктор** из 8 категорий действий: задания, обработка документа, конструкции, уведомления, CRM, диск, прочее, действия приложений.
4. **Задания — это диалог, уведомления — монолог.** Задания ждут ответа пользователя; уведомления информируют без ожидания. Путаница между ними — типичная ошибка.
5. **Параметры действий должны быть динамическими.** Статичные значения — редкость; данные берутся из полей документа, переменных БП, результатов предыдущих действий.
6. **Фильтрация по типу защищает от ошибок.** Форма «Вставка значений» показывает только совместимые по типу поля — нельзя случайно вставить дату вместо пользователя.
7. **Калькулятор — формульный режим любого поля.** Знак `=` активирует вычисление; функция `addworkdays(дата, N)` — стандартный инструмент для бизнес-дедлайнов с учётом рабочего календаря.
8. **Модификатор `printable` обязателен** при выводе пользователей, статусов и справочников в текстах уведомлений. Без него пользователи видят числовые ID вместо имён.
9. **Модификаторы и калькулятор — разные слои:** модификатор меняет формат готового значения, калькулятор вычисляет новое. Работают совместно в сложных сценариях.
10. **Веб-хук и «Запуск БП»** — главные инструменты расширения автоматизации за пределы одного процесса: веб-хук интегрирует внешние системы, «Запуск БП» создаёт цепочки внутри Bitrix24.
11. **«Прерывание процесса» + режим «Запуск при изменении»** = быстрый цикл отладки без создания новых документов при каждой проверке.
12. **Именование действий — инвестиция в будущее.** Понятные названия критичны для поддержки, доработки и командной работы с шаблонами.
13. **Правильная точка вставки действия определяет бизнес-смысл.** Задача перед бухгалтерской цепочкой становится обязательным шлюзом — логика размещения важна не меньше настройки параметров.
14. **Документация — неотъемлемая часть работы.** Для каждой категории действий, калькулятора и модификаторов есть официальные страницы, которые разработчики БП используют постоянно.
15. **Начинать освоение правильнее с изменения типового шаблона**, а не с создания с нуля — это быстрее даёт понимание структуры, снижает риск ошибок и показывает проверенные паттерны автоматизации.
