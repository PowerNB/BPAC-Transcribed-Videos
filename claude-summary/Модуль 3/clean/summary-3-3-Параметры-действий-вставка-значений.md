# Параметры действий: вставка значений

## О чём этот урок

Урок посвящён параметрам действий в дизайнере бизнес-процессов Bitrix24 и механизму **вставки динамических значений** в поля параметров. На практическом примере (шаблон «Заявка на отпуск») разбирается, как добавить действие в нужную точку шаблона, настроить его параметры и подставить в них данные из полей документа, переменных, системных данных и результатов предыдущих действий.

---

## Основные понятия

### Параметры действия
Каждое действие в шаблоне БП имеет собственные настройки, определяющие его поведение:

| Параметр | Что задаёт |
|---|---|
| **Кому** | Конкретный пользователь, роль, поле документа |
| **Что делать** | Текст задания, тема уведомления |
| **Когда** | Срок, условие выполнения |
| **Какие данные использовать** | Поля документа, переменные БП, константы |

### Динамические значения
Вместо статичного текста в параметрах можно использовать **динамические значения** — данные, которые система подставляет в момент выполнения процесса:
- Поля документа (например, `{=Document:NAME}` — имя документа)
- Переменные БП, заданные в шаблоне
- Результаты предыдущих действий
- Системные данные (текущая дата, пользователь и т. д.)

### Синтаксис подстановки
После выбора значения оно вставляется в поле в виде конструкции:
```
{=Document:FIELD_CODE}
```
- Это **инструкция для системы**, а не просто текст
- В момент выполнения БП система заменяет конструкцию на реальное значение
- Статический текст и динамические значения **можно комбинировать** в одном поле

> **Пример:** `Передача дел — {=Document:CREATED_BY} уходит в отпуск`

---

## Практический пример: шаблон «Заявка на отпуск»

### Задача
При одобрении отпуска руководителем — автоматически создавать задачу **уходящему в отпуск сотруднику** с требованием расписать передачу дел: кто и чем занимается в его отсутствие.

### Структура шаблона и точка вставки

В шаблоне есть ветвление:
- **Если отпуск утверждён** → сюда встраивается задача
- Если отпуск не утверждён → другая ветка

**Точка вставки:** сразу после утверждения отпуска, **перед** тем как бухгалтеру уходит цепочка на оформление.

> **Логика:** пока задача по передаче дел не закрыта, процесс не продвигается к бухгалтерии — отпуск не будет оформлен. Это мотивирует сотрудника быстро завершить передачу дел.

## Пошаговые инструкции

### 1. Добавление действия в нужную точку шаблона

**Способ 1 — Перетаскивание (менее удобный):**
1. Найти нужное действие на панели справа
2. Перетащить его в нужное место рабочей области

> ⚠️ Неудобно, если панель с действиями находится далеко от точки вставки (например, действия вверху, а точка — внизу длинного шаблона)

**Способ 2 — Контекстное меню (рекомендуется):**
1. Навести курсор на **стрелку-связь** между действиями в нужном месте
2. Нажать на стрелку — появится контекстное меню
3. Выбрать нужное действие из списка
4. Действие добавляется **точно в выбранную позицию**

---

### 2. Открытие и настройка параметров действия

1. Нажать на добавленное действие в рабочей области дизайнера
2. Откроется форма **«Настройки параметров действия»**
3. Заполнить поля, специфичные для данного типа действия

> **Пример для действия «Задача»:** название, постановщик, ответственные, исполнители, крайний срок и т. д.

---

### 3. Настройка параметра «Остановить процесс на время выполнения задачи»

Это специальный параметр действия «Задача»:

| Значение | Поведение БП |
|---|---|
| **Да** | БП приостанавливается и ждёт закрытия задачи |
| **Нет** | БП продолжает выполнение, не дожидаясь задачи |

В примере с отпуском → ставить **«Да»**, чтобы сотрудник не мог уклониться от передачи дел.

---

### 4. Вставка динамического значения в поле параметра

1. Нажать **кнопку вставки значений** рядом с нужным полем параметра
2. Откроется форма **«Вставка значений»**
3. Выбрать нужное значение из одного из доступных блоков
4. Значение вставится в поле в виде конструкции `{...}`

---

## Форма «Вставка значений»: детальный разбор

### Блоки доступных значений (7 блоков)

#### 1. Параметры шаблона
- Значения, определённые разработчиком на уровне шаблона БП
- В типовых шаблонах могут быть пустыми — используются при создании шаблонов с нуля

#### 2. Переменные
- Временные переменные, объявленные разработчиком при создании БП
- Хранят **промежуточные данные** внутри процесса

#### 3. Константы
- Постоянные значения, заданные разработчиком в шаблоне
- **Не меняются** в ходе выполнения процесса

> ℹ️ Параметры шаблона, переменные и константы **определяются разработчиком** при проектировании шаблона. Подробнее — в следующих уроках.

#### 4. Поля документа
- Поля объекта, по которому запущен бизнес-процесс
- **Ключевая особенность:** отображаются только поля, **совместимые по типу** с параметром, в который вставляется значение

#### 5. Дополнительные результаты
- Значения, «оставшиеся» после выполнения предыдущих действий в БП
- **Пример:** действие «Выбор сотрудника» сохраняет выбранного пользователя → здесь можно к нему обратиться
- Позволяет **передавать данные между действиями** в рамках одного БП

#### 6. Пользователи
- Выбор конкретного сотрудника из базы

#### 7. Категория пользователей
- Выбор группы сотрудников: отдел, группа, роль и т. д.

---

### Фильтрация по типу — ключевое поведение

Форма «Вставка значений» **автоматически фильтрует** доступные значения в зависимости от типа целевого поля:

| Тип параметра | Что отображается в «Полях документа» |
|---|---|
| Пользователь / Сотрудник | Только поля типа «пользователь» |
| Текст | Все поля |
| Дата | Только поля типа «дата» |

> **Зачем это нужно:** защита от некорректной подстановки — система не позволяет вставить дату туда, где ожидается имя пользователя.

## Хорошие практики именования действий

> «Когда вы создаёте и размещаете действия в бизнес-процессе, их явное именование поможет потом ориентироваться, чтобы вернуться к своим работам, понять, что у вас там происходило, и дорабатывать даже собственный бизнес-процесс через некоторое время»

**Правило:** давайте действиям **понятные, описательные названия**, отражающие суть того, что они делают.

Это критично для:
- Поддержки и доработки шаблонов через время
- Командной работы
- Отладки сложных шаблонов

## Главное

1. **Параметры действий могут быть динамическими.** Не нужно вписывать статические значения — можно подставить данные из документа, переменных или результатов других действий.

2. **Форма «Вставка значений» содержит 7 блоков:** параметры шаблона, переменные, константы, поля документа, дополнительные результаты, пользователи, категории пользователей.

3. **Тип поля определяет доступные значения.** Форма вставки автоматически фильтрует значения по совместимому типу — это защита от ошибок несовместимости данных.

4. **«Дополнительные результаты» — мост между действиями.** Если предыдущее действие что-то «вычислило» или «выбрало» (например, нашло руководителя), эти данные доступны в последующих действиях через этот блок.

5. **Синтаксис подстановки `{...}`** — не просто текст, а инструкция системе. В момент выполнения БП конструкция заменяется на реальные данные. Статический текст и динамические значения можно комбинировать в одном поле.

6. **Параметр «Остановить процесс» — инструмент контроля.** Если задача должна обязательно завершиться до продолжения процесса — ставьте «Да». Это создаёт «блокер» для движения вперёд.

7. **Добавлять действия удобнее через контекстное меню стрелки-связи**, а не перетаскиванием — это точнее позиционирует действие в нужном месте шаблона.

8. **Именуйте действия явно.** Понятные названия — инвестиция в поддержку шаблонов в будущем, особенно при командной работе.

9. **Начинать осваивать параметры удобно через изменение типового шаблона.** Добавь одно действие с динамическим параметром к реальному процессу — это даёт быстрое понимание механики.

10. **Логика размещения действия важна:** правильная точка вставки (например, перед бухгалтерской цепочкой) определяет бизнес-смысл автоматизации — в примере задача становится обязательным шлюзом перед оформлением отпуска.
