# Калькулятор

## О чём этот урок

Урок посвящён инструменту **Калькулятор** в Bitrix24 — встроенной возможности вычислять значения прямо внутри параметров действий бизнес-процесса. Рассматривается синтаксис формул, работа с датами, переменными и полями документа, а также техники быстрой отладки.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Калькулятор** | Встроенная возможность любого поля параметров действий вычислять значения по формуле |
| **Режим формулы** | Активируется знаком `=` в начале значения поля |
| **Подстановка** | Синтаксис `{Document:FIELD}` — вставка значения из поля документа |
| **Контейнер формулы** | Синтаксис `{{= }}` — обёртка для вычисления внутри текстовой строки |
| **`addworkdays()`** | Встроенная функция для прибавления рабочих дней к дате |
| **«Остановить процесс»** | Действие-отладчик, прерывающее выполнение БП после указанной точки |

> **Полная документация:** https://helpdesk.bitrix24.ru/open/5428897/ — одна из наиболее востребованных страниц для разработчиков БП.

---

## Назначение Калькулятора

Калькулятор используется там, где нужное значение **нельзя взять напрямую** из документа или переменных — его нужно **вычислить**.

**Типичный пример:** крайний срок задачи.
- Нельзя просто взять дату из поля — нужно посчитать «дата согласования + 2 рабочих дня»
- Именно для этого используется калькулятор

**Принцип освоения из урока:**
> «Сначала учимся вычислять 2+2 — потом узнаём про море возможностей»

---

## Как работает Калькулятор

### Базовый принцип

Калькулятор — это **не отдельное действие** в дизайнере БП. Это встроенная возможность **любого поля** параметров действий.

- Если в поле параметра ввести значение, начинающееся со знака `=`, система интерпретирует содержимое как **формулу**
- Результат вычисляется **перед выполнением действия**, а не как текст

> «Фактически система сейчас нам будет вычислять эти значения. То есть не текст нам напишет равно 2 плюс 2, а вычислит 4 и отправит в виде сообщения.»

---

## Три синтаксиса для вычислений

### 1. Полное поле — только формула

```
=2+2
```

- Всё поле параметра является формулой
- Результат: `4`
- Применяется, когда поле должно содержать **только** вычисленное значение

---

### 2. Формула внутри текста — двойные скобки

```
Вам сообщение: {{=2+2}}
```

- Часть текста — статическая, часть — вычисляемая
- Результат: `Вам сообщение: 4`
- Применяется, когда нужно сформировать **текстовое сообщение** с вычисленными вставками

---

### 3. Формула с полями документа

```
2 + ID элемента: {{=2+{Document:ID}}}
```

- Внутри `{{= }}` используется подстановка `{Document:ID}` — значение из поля документа
- Результат при ID=5: `2 + ID элемента: 7`
- Позволяет **комбинировать переменные БП с арифметикой**

> **Важно:** одинарные фигурные скобки `{Document:ID}` — синтаксис подстановки, генерируемый формой «Вставка значений». Двойные `{{= }}` — синтаксис калькулятора, оборачивающий формулу.

## Возможности Калькулятора

### Интерфейс при вводе `=`

При вводе знака `=` в поле параметра появляется **специальная форма** с доступными элементами:

| Категория | Что входит |
|---|---|
| **Переменные** | Параметры шаблона, переменные, константы |
| **Поля документа** | Все поля объекта, по которому запущен БП |
| **Дополнительные результаты** | Результаты выполненных ранее действий |
| **Константы** | Заданные разработчиком постоянные значения |
| **Системные переменные** | Время сервера, локальное время, текущая дата |
| **Функции** | Большой набор встроенных функций |

---

### Категории доступных операций

#### Математические операции
- Сложение `+`, вычитание `-`, умножение `*`, деление `/`
- Возведение в степень
- Остаток от деления
- Любые арифметические выражения

#### Операции сравнения
- `>`, `<`, `>=`, `<=`, `=`, `!=`
- Результат — логическое значение (истина/ложь)

#### Логические операции
- `AND`, `OR`, `NOT`
- Построение составных условий

#### Математические функции
- Округление, абсолютное значение, квадратный корень и др.

#### Функции для работы с датами
- **`addworkdays(дата, N)`** — добавить N рабочих дней (пропускает выходные)
- Добавить/вычесть дни, часы, минуты
- Вычислить разницу между датами
- Форматировать дату в строку
- Получить отдельные компоненты даты (день, месяц, год)

#### Условные выражения (IF)
```
IF(условие, значение_если_да, значение_если_нет)
```
- Аналог тернарного оператора

#### Работа с массивами
- Операции над массивами значений

## Практический пример: вычисление даты дедлайна

### Задача
После того как руководитель одобрил отпуск — автоматически создать задачу сотруднику на передачу дел. **Дедлайн задачи** = текущая дата + 2 рабочих дня.

Нельзя просто взять поле даты из документа — нужно **вычислить**: прибавить именно рабочие дни, не календарные.

### Решение: функция `addworkdays()`

```
addworkdays(текущая дата, 2)
```

Функция принимает два аргумента:
1. **Базовая дата** — переменная «Текущая дата» (берётся из формы вставки значений, системная переменная `{=system:Now}`)
2. **Количество рабочих дней** для добавления

### Формула в поле параметра

```
{{=addworkdays({=system:Now}, 2)}}
```

### Проверка корректности (тест из урока)

| День | Дата | Статус |
|---|---|---|
| Суббота | 19-е | Выходной — пропускается |
| Воскресенье | 20-е | Выходной — пропускается |
| Понедельник | 21-е | 1-й рабочий день |
| Вторник | 22-е | 2-й рабочий день ✓ |

**Результат: 22-е** — функция корректно пропустила выходные.

## Техника отладки при работе с Калькулятором

### Приём «Изолировать действие»

При эксперименте с формулой не нужно запускать весь БП целиком.

1. После тестируемого действия (например, «Сообщение») вставить действие **«Остановить процесс»**
2. БП выполнит только первое действие и остановится — остальные шаги не пройдут
3. Можно быстро проверять результаты без «шума» от остальных действий

---

### Режим «Запуск при изменении»

- Настройка шаблона: **запуск при изменении документа**
- Позволяет многократно перезапускать БП, просто открыв документ и нажав «Применить»
- Не нужно каждый раз создавать новый документ — один и тот же изменяется снова и снова

---

### Алгоритм быстрого тестирования

```
1. Настроить шаблон на «Запуск при изменении»
2. Вставить тестируемое действие (например, «Сообщение» с формулой)
3. Вставить «Остановить процесс» сразу после
4. Сохранить шаблон
5. Открыть тестовый документ → Применить
6. Проверить результат в уведомлениях
7. Скорректировать формулу → Сохранить → повторить
```

## Пошаговые инструкции

### Ввести простую формулу в поле параметра действия

1. Открыть параметры нужного действия в дизайнере БП
2. Нажать на нужное поле параметра
3. Ввести `=` — появится форма с доступными переменными и функциями
4. Скрыть форму (если мешает) и вписать формулу вручную, например `=2+2`
5. Сохранить параметры

> При вводе `=` система активирует режим вычисления — поле будет не текстовым, а формульным.

---

### Вставить вычисление внутри текстового сообщения

1. Открыть параметры действия «Сообщение»
2. В поле текста сообщения написать, например: `Вам сообщение: {{=2+2}}`
3. Конструкция `{{= }}` — контейнер для формулы внутри текстовой строки
4. Внутри `{{= }}` можно использовать те же формулы и функции, что и в полном режиме

---

### Использовать поле документа в формуле

1. Написать начало формулы: `{{=2+`
2. Открыть форму вставки значений (кнопка рядом с полем) или вставить через `=`-форму
3. Выбрать нужное поле документа, например «ID элемента»
4. Система вставит синтаксис: `{Document:ID}`
5. Закрыть скобку: `{{=2+{Document:ID}}}`
6. Результат: при выполнении БП значение ID будет подставлено и посчитано

---

### Вычислить дату через N рабочих дней

1. Открыть параметры действия, поле типа «Дата» (например, «Крайний срок» у задачи)
2. Активировать режим калькулятора, введя `=`
3. Найти функцию `addworkdays` в документации: принимает `(дата, N)`
4. Составить формулу: `addworkdays({=system:Now}, 2)` — или через форму выбрать «Текущая дата» и обернуть в функцию
5. Сохранить — при выполнении БП автоматически прибавит 2 рабочих дня к текущей дате

---

## Главное

1. **Калькулятор — не отдельное действие, а режим любого поля.** Знак `=` в начале значения переключает поле из текстового в формульный режим.
2. **Два синтаксиса для двух задач:** `=формула` — когда всё поле является вычислением; `{{=формула}}` — когда нужно вставить вычисление **внутри текста**.
3. **Поля документа и переменные работают прямо внутри формул.** Синтаксис `{Document:FIELD}` внутри `{{= }}` позволяет вычислять на основе реальных данных документа.
4. **`addworkdays(дата, N)` — ключевая функция для бизнес-задач с датами.** Добавляет именно рабочие дни, автоматически пропуская выходные — стандартная потребность при постановке сроков.
5. **Начинать стоит с простого: `=2+2`.** Убедиться, что принцип работает, потом усложнять — это снижает риск путаться в синтаксисе при первом знакомстве.
6. **Действие «Остановить процесс» — главный инструмент отладки.** Вставь его после тестируемого действия — БП не пойдёт дальше, пока не разберёшься с формулой.
7. **Режим «Запуск при изменении» + «Остановить процесс» = быстрый цикл тестирования.** Изменил → Применил → Проверил уведомление → Скорректировал. Без создания новых документов каждый раз.
8. **Калькулятор нужен для вычисляемых значений.** Если нужно «дата + N дней» или любая другая формула — это калькулятор, а не просто вставка значения из поля.
9. **Полная документация (helpdesk.bitrix24.ru/open/5428897/) — обязательна к изучению.** Там математика, даты, логика, условия IF, массивы — эту страницу разработчики БП используют постоянно.
10. **Калькулятор охватывает широкий спектр операций:** арифметика, сравнение, логика, функции дат, условные выражения IF, работа со строками и массивами — всё доступно в любом поле параметра действия.
