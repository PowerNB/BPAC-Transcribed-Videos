# Модификаторы

## О чём этот урок

Урок посвящён модификаторам в бизнес-процессах Bitrix24 — инструменту, который позволяет преобразовывать тип или формат значения **в момент его вставки** в параметры действий. Основная практическая задача — сделать уведомления и сообщения читаемыми для пользователей, а не заполненными системными идентификаторами.

---

## Основные понятия

### Модификатор
**Преобразование**, применяемое к значению **в момент его вставки** в параметр действия. Не требует дополнительных шагов в шаблоне — модификатор указывается прямо при подстановке значения.

### Что может делать модификатор
- Преобразовывать **тип данных**: строка → число, число → строка, дата → строка
- **Форматировать** значения: задавать формат даты (`ДД.ММ.ГГГГ`), добавлять разделители тысяч у чисел
- Переводить **системные идентификаторы** в читаемый текст
- Изменять **регистр** текста, обрезать, заменять символы
- Обеспечивать **корректное сравнение** значений в условиях (приведение типов)

### Отличие от Калькулятора
| Инструмент | Задача |
|---|---|
| **Модификатор** | Изменяет **формат/тип** уже существующего значения |
| **Калькулятор** | **Вычисляет** новое значение на основе формулы |

В сложных формулах оба инструмента могут использоваться совместно.

## Проблема: технические значения вместо читаемых данных

### Суть проблемы
Многие поля документов и переменные бизнес-процессов в Bitrix24 хранят **не текстовые значения**, а **системные идентификаторы**:

| Поле | Что хранится | Что ожидает пользователь |
|---|---|---|
| «Кем создан» (`createdby`) | Числовой ID пользователя (например, `42`) | Имя: «Иван Иванов» |
| Поле статуса | Числовой код | Название статуса |
| Ответственный | ID пользователя | Имя пользователя |

### Последствие без модификатора
При стандартной подстановке пользователь получает сообщение вида:
```
Документ создан: 42
```
Вместо ожидаемого:
```
Документ создан: Иван Иванов
```

### Пример из урока
1. В действие «Уведомления / Сообщения соцсети» добавлено поле `createdby` **без модификатора** → результат: нечитаемое системное значение
2. То же поле `createdby` добавлено **с модификатором `printable`** → результат: читаемое имя пользователя
3. Оба значения выведены рядом — разница наглядна

> *«То есть первое это вообще-то малоинформативное сообщение для пользователя. Это универсистемная переменная, которая используется. А это уже читаемое значение. Кто этот самый пользователь.»*

## Модификатор `printable`

### Назначение
`printable` — **основной и наиболее часто используемый модификатор**. Переводит техническое/системное значение в **человекопонятный читаемый вид**.

### Когда применять
- При использовании полей типа «Пользователь» в текстовых сообщениях
- При выводе значений справочников (хранят коды — нужны названия)
- При использовании любой переменной, которая хранит ID, а не текст
- Всякий раз, когда в уведомлении вместо имени/названия показывается число

### Синтаксис
Модификатор добавляется к стандартной конструкции вставки значения:

```
Без модификатора:   {Document:FIELD}
С модификатором:    {Document:FIELD|printable}
```

Точный синтаксис и все варианты — в официальной документации: **https://helpdesk.bitrix24.ru/open/5426411/**

## Категории модификаторов (обзор по документации)

| Группа | Что делают | Когда использовать |
|---|---|---|
| **Преобразование типов** | Конвертируют значение из одного типа в другой (число → строка, дата → строка и т.п.) | При несовместимости типов в условиях и действиях |
| **Форматирование** | Задают формат отображения (формат даты, количество знаков после запятой и пр.) | При выводе дат и чисел в нужном виде |
| **Читаемый вид** | `printable` и аналоги — из системного в человекопонятное | При выводе ID пользователей, кодов справочников |
| **Работа с текстом** | Изменение регистра, обрезка, замена символов | При форматировании строк |

> Для базовой работы достаточно знать `printable`. Остальные модификаторы изучаются по мере необходимости из документации.

## Пошаговые инструкции

### Инструкция 1: Применить модификатор к вставляемому значению

1. Открыть параметры нужного **действия** (например, «Уведомления / Сообщения соцсети»)
2. В нужном текстовом поле параметра нажать кнопку **«Вставка значений»**
3. Найти нужное поле (например, «Кем создан» / `createdby`)
4. В форме вставки найти пункт **выбора модификатора**
5. Выбрать модификатор **`printable`**
6. Подтвердить вставку
7. Сохранить параметры действия

> **Альтернативный способ:** Посмотреть синтаксис в документации (https://helpdesk.bitrix24.ru/open/5426411/) и **дописать модификатор вручную** к уже вставленному значению прямо в поле параметра.

---

### Инструкция 2: Проверить работу модификатора (быстрый тест)

1. Убедиться, что шаблон БП настроен на режим **«Запуск при изменении»** (позволяет тестировать на одном документе без создания нового)
2. В тестовом действии «Сообщение» вставить **одно и то же поле дважды**:
   - Первая вставка — **без модификатора** (для сравнения)
   - Вторая вставка — **с модификатором `printable`**
3. Добавить действие **«Прерывание процесса»** сразу после тестового действия
4. Сохранить шаблон
5. Открыть тестовый документ → нажать **«Применить»** (или сохранить любое изменение)
6. Открыть **уведомления / ленту** — сравнить два значения
7. Убедиться: первое значение — системный ID, второе — читаемое имя пользователя

## Главное

1. **Модификатор** — это преобразование, применяемое к значению **в момент вставки**; изменяет тип или формат, не вычисляя ничего нового.
2. **Поля в Bitrix24 хранят системные ID**, а не читаемый текст: числовые ID пользователей, коды статусов и справочников — это норма, но без модификатора пользователи видят «мусор».
3. **`printable` — главный модификатор для практики**: если в уведомлении вместо имени пользователя показывается число — первым делом ставь `printable`.
4. **Модификатор указывается при вставке значения**, а не после; это часть синтаксиса подстановки: `{Document:FIELD|printable}`.
5. **Без `printable` уведомления выглядят как системный лог** — пользователи не должны видеть числовые ID; модификаторы обязательны для production-качества БП.
6. **Модификаторы и Калькулятор — разные инструменты**: модификатор меняет формат существующего значения, калькулятор вычисляет новое; в сложных формулах могут работать вместе.
7. **Всегда сверяйся с таблицей модификаторов** (helpdesk.bitrix24.ru/open/5426411/) — там все доступные преобразования, типы и синтаксис.
8. **Тестируй с двумя вставками рядом** — одна без модификатора, другая с `printable`; это наглядно подтверждает корректность применения.
9. **Режим «Запуск при изменении» ускоряет разработку** — не нужно создавать новый документ для каждой проверки.
10. **Модификаторы решают проблему несовместимости типов**: если значение вставляется некорректно или в неверном формате — первым делом проверяй наличие и правильность модификатора.
