# Модуль 3, Урок 6: Дизайнер бизнес-процессов и действия в Bitrix24

## О чём этот урок

Урок рассматривает бизнес-процессы Bitrix24 с точки зрения разработчика: из каких блоков состоит шаблон БП, какие группы действий доступны в дизайнере, как работают параметры действий, вставка значений, калькулятор и модификаторы. Понимание этих базовых элементов — фундамент для создания собственных бизнес-процессов.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Шаблон БП** | Описание логики бизнес-процесса в дизайнере; не является запущенным процессом — это «чертёж» |
| **Запущенный БП** | Конкретный экземпляр шаблона, работающий по реальному объекту |
| **Документ** | Текущий объект, по которому запущен бизнес-процесс (например, строка в таблице отпусков, сделка в CRM) |
| **Действие** | Атомарный шаг в шаблоне БП (отправить уведомление, создать задание, изменить поле и т. д.) |
| **Конструкция** | Управляющая структура: ветвление (условие), цикл, прерывание и т. д. |
| **Цикл** | Блок действий, который повторяется до достижения заданного условия |
| **Действия приложений** | Кастомные действия, добавляемые через приложения Bitrix24 (требуют разработки) |
| **Веб-хук** | HTTP-запрос к внешней системе с передачей данных через параметры URL |
| **Калькулятор** | Встроенный инструмент для вычисления значений внутри БП |
| **Модификатор** | Инструмент преобразования типов и форматов данных внутри БП |
| **Копия шаблона** | Экспорт/импорт шаблона БП для переноса или резервирования |

---

## Структура дизайнера БП

Дизайнер — это визуальный редактор шаблонов. Шаблон строится из **действий**, расположенных в рабочей области. Справа панель со всеми доступными действиями, сгруппированными по блокам.

### Визуальные элементы шаблона

- **Последовательность действий** — линейная цепочка шагов
- **Ветвления (условия)** — развилки с несколькими путями выполнения
- **Циклы** — блоки, обведённые замкнутыми линиями; повторяются, пока не выполнено условие выхода

> Пример из урока: сложный типовой шаблон содержит многократные условия и циклы — это нормально для реальных процессов.

---

## Блоки действий в дизайнере

### 1. Обработка документа
**Назначение:** работа с текущим объектом (документом), по которому запущен БП.

Ключевые возможности:
- **Изменение документа** — записать значение в поле объекта (например, дата согласования, ответственный руководитель)
- **Запуск бизнес-процесса** — запустить *другой* БП по *любому другому* объекту системы (не только текущему)

> Пример: в процессе согласования отпуска «документ» — это строка в таблице отпусков. Действие «Изменить документ» сохраняет в неё поля «Руководитель, согласовавший отпуск» и «Дата согласования».

> Важно: действие «Запуск БП» даёт мощные возможности для цепочек автоматизации — один процесс может инициировать другой по совершенно иному объекту.

**Документация:** https://helpdesk.bitrix24.ru/open/7449433/

---

### 2. Задания
**Назначение:** интерактив с пользователем — создание интерфейса для принятия решений.

Это то, что пользователь видит в системе в виде сообщений типа:
- «Вам необходимо согласовать»
- «Вам необходимо утвердить / одобрить»

Задания создают **диалог между процессом и человеком**: процесс ждёт ответа пользователя, прежде чем двигаться дальше.

**Документация:** https://helpdesk.bitrix24.ru/open/7451037/

---

### 3. Конструкции
**Назначение:** управляющие структуры, задающие логику выполнения процесса.

Включают:
- **Условия / ветвления** — выбор пути в зависимости от данных
- **Циклы** — повторение блока действий
- **Более сложные конструкции** — описаны в документации

**Документация:** https://helpdesk.bitrix24.ru/open/7453445/

---

### 4. Уведомления
**Назначение:** коммуникация с пользователями без ожидания их ответа.

Варианты:
- Отправить **сообщение в чат**
- Написать в **живую ленту**
- Поставить **задачу** (логически ближе к блоку «Задания», но находится здесь)

> Разница от блока «Задания»: уведомления — одностороннее информирование, задания — двусторонний диалог с ожиданием действия пользователя.

**Документация:** https://helpdesk.bitrix24.ru/open/7471547/

---

### 5. Действия приложений
**Назначение:** кастомные (нестандартные) действия, добавляемые через приложения Bitrix24.

Когда использовать:
- Стандартных блоков недостаточно для реализации логики
- Нужна специфическая интеграция или функциональность

Как добавить кастомное действие:
1. Написать код действия (требуются компетенции программиста)
2. Обернуть в приложение для Bitrix24
3. Загрузить приложение на портал
4. Действие появится в этом блоке дизайнера

> Работает в том числе в облачном Bitrix24.

---

### 6. CRM
**Назначение:** работа с объектами CRM-системы.

Возможности:
- **Создание объектов:** контакты, лиды, компании, сделки
- **Получение данных** из CRM
- **Выбор данных в CRM** — особенно полезное действие для поиска и фильтрации

**Документация:** https://helpdesk.bitrix24.ru/open/7567357/

---

### 7. Диск
**Назначение:** работа с файлами и папками на Диске Bitrix24.

**Документация:** https://helpdesk.bitrix24.ru/open/7544195/

---

### 8. Прочее
**Назначение:** полезные действия, не вошедшие в другие блоки.

Ключевые действия:

| Действие | Описание |
|---|---|
| **Выбор сотрудника** | Определяет конкретного пользователя: руководителя, участника группы, кого-то из заранее известного списка |
| **Прерывание процесса** | Останавливает выполнение БП при наступлении условия — логически близко к конструкциям, но здесь |
| **Веб-хук** | Вызывает внешний URL с передачей данных через параметры — простой способ интеграции с внешними системами |

> Пример использования веб-хука: в нужный момент БП отправляет HTTP-запрос во внешнюю CRM, ERP или мессенджер, передавая данные (ID сделки, сумму, ответственного и т. д.) через параметры URL.

**Документация:** https://helpdesk.bitrix24.ru/open/7557393/

## Параметры действий и вставка значений

Каждое действие в дизайнере имеет **настраиваемые параметры**. При заполнении параметров можно использовать не только статические значения, но и **динамические** — вставлять значения из:

- полей текущего документа
- результатов предыдущих действий
- системных переменных (дата, время, текущий пользователь и т. д.)

Вставка значений осуществляется через специальный интерфейс выбора переменных прямо в поле параметра.

## Калькулятор

Встроенный инструмент для **вычисления значений** внутри бизнес-процесса.

Применение:
- Арифметические операции (начиная с простого `2 + 2`)
- Вычисление дат (например, «дата + 3 рабочих дня»)
- Условные вычисления
- Широкий спектр формул — подробнее в документации

**Документация:** https://helpdesk.bitrix24.ru/open/5428897/

---

## Модификаторы

Инструмент для **преобразования данных** — изменения типа или формата значения.

Применение:
- Преобразование типов данных (строка → число, дата → строка и т. д.)
- Форматирование значений перед использованием в действиях
- Таблица всех доступных преобразований — в документации

**Документация:** https://helpdesk.bitrix24.ru/open/5426411/

## Копия шаблона БП

**Копия шаблона = экспорт + импорт.**

Используется для:
- Переноса шаблона между порталами
- Создания резервной копии перед изменениями
- Тиражирования готового шаблона

> Важное различие: **шаблон** — это описание процесса (чертёж), **запущенный БП** — это живой экземпляр, работающий по конкретному объекту. Копируется именно шаблон, а не запущенные процессы.

---

## Практика: изменение типового БП

Рекомендуемый порядок освоения:

1. Найти типовой (стандартный) шаблон БП в системе
2. Изучить его структуру — какие блоки использованы, как они связаны
3. Внести небольшое изменение (модифицировать параметр действия, добавить уведомление)
4. Запустить и проверить результат

Это безопаснее, чем создавать процесс с нуля — типовые шаблоны содержат проверенную логику.

---

## Главное

1. **Документ = текущий объект БП.** Всё, что делает блок «Обработка документа», применяется именно к нему — к той сущности (строке, сделке, задаче), по которой запущен процесс.

2. **Блок «Задания» = диалог с человеком.** Когда нужно, чтобы пользователь что-то подтвердил или выбрал — это блок «Задания», а не «Уведомления».

3. **Кастомные действия реальны даже в облаке.** Если стандартных блоков не хватает, можно написать приложение и добавить своё действие в дизайнер.

4. **Веб-хук — быстрая интеграция без разработки API.** Для простой передачи данных во внешнюю систему достаточно одного действия «Веб-хук» без написания кода.

5. **«Запуск БП» — инструмент цепочек автоматизации.** Один процесс может запустить другой по любому объекту системы — это открывает возможности для сложных сценариев.

6. **Шаблон ≠ запущенный процесс.** Копируется, экспортируется и импортируется именно шаблон. Работающие экземпляры существуют отдельно.

7. **Калькулятор и модификаторы — мощные инструменты данных.** Вычисление значений и преобразование типов позволяют строить гибкую логику без кода.

8. **Начинать лучше с изменения типового БП**, а не с создания с нуля — это быстрее даёт понимание структуры и снижает риск ошибок.

9. **Документация по каждому блоку действий** доступна на helpdesk.bitrix24.ru — ссылки приведены в каждом разделе этого конспекта.
