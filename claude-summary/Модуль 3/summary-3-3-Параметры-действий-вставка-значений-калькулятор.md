# Модуль 3, Урок 3: Параметры действий, вставка значений и калькулятор

## О чём этот урок

Урок посвящён практической работе с параметрами действий в дизайнере бизнес-процессов Bitrix24: как заполнять поля действий не статическими значениями, а динамическими — вставлять данные из полей документа, результатов предыдущих действий, переменных и констант. Также вводятся понятия «Калькулятор» и «Модификаторы» — инструменты для вычисления значений и преобразования типов данных внутри бизнес-процесса.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Параметры действия** | Набор настраиваемых полей конкретного действия в дизайнере БП (например, для задачи — название, ответственный, срок и т. д.) |
| **Вставка значений** | Механизм подстановки динамических данных в поле параметра действия через специальную форму выбора |
| **Поля документа** | Поля объекта (сущности), по которому запущен бизнес-процесс (например, поля заявки на отпуск) |
| **Параметры шаблона** | Значения, определённые на уровне шаблона БП разработчиком при его создании |
| **Переменные** | Временные переменные внутри БП, определяемые разработчиком при создании шаблона |
| **Константы** | Постоянные значения внутри БП, определяемые разработчиком при создании шаблона |
| **Дополнительные результаты** | Значения, которые «остаются» от исполнения предыдущих действий в БП и доступны для использования дальше |
| **Калькулятор** | Встроенный инструмент для вычисления значений прямо внутри БП (арифметика, даты, формулы) |
| **Модификаторы** | Инструменты преобразования типов и форматов данных при вставке значений |
| **Синтаксис подстановки** | Конструкция в фигурных скобках `{...}`, которая формируется при вставке значения и используется системой для подстановки данных в момент выполнения |
| **Остановить процесс на время выполнения задачи** | Параметр задачи в БП: если «Да» — процесс не пойдёт дальше, пока задача не будет закрыта |

---

## Практический пример: добавление задачи в шаблон «Заявка на отпуск»

Для иллюстрации работы с параметрами действий в уроке используется конкретный кейс — доработка типового шаблона бизнес-процесса согласования отпуска.

### Задача
При одобрении отпуска руководителем — автоматически создавать задачу **уходящему в отпуск сотруднику** с требованием расписать передачу дел: кто и чем занимается в его отсутствие.

### Место встройки действия в шаблон

В шаблоне есть ветвление:
- **Если отпуск утверждён** → нужно встроить задачу сюда
- Если отпуск не утверждён → другая ветка

Точка вставки: **сразу после утверждения отпуска**, перед тем как бухгалтеру уходит цепочка на оформление.

> **Почему именно здесь:** задача становится мотивацией быстро передать дела — пока задача не закрыта, процесс не дойдёт до бухгалтерии и отпуск не будет оформлен.

---

## Пошаговые инструкции

### Как добавить действие в нужную точку шаблона

Два способа:

**Способ 1 — перетаскивание:**
1. Найти нужное действие на панели справа
2. Перетащить его в нужное место рабочей области
> Неудобно, если панель с действиями далеко от точки вставки (например, действия вверху, а точка внизу длинного шаблона)

**Способ 2 — контекстное меню (рекомендуется):**
1. Навести курсор на стрелку-связь между действиями в нужном месте
2. Нажать на стрелку — появится контекстное меню
3. Выбрать нужное действие из списка
4. Действие добавляется точно в выбранную позицию

---

### Как открыть и настроить параметры действия

1. Нажать на добавленное действие в рабочей области дизайнера
2. Откроется форма **«Настройки параметров действия»**
3. Форма содержит поля, специфичные для данного типа действия

> **Пример:** для действия «Задача» — это поля задачи: название, постановщик, ответственные, исполнители, крайний срок и т. д.

---

### Параметр «Остановить процесс на время выполнения задачи»

Это особый параметр действия «Задача»:
- **Да** — БП приостанавливается и ждёт, пока задача не будет закрыта
- **Нет** — БП продолжает выполнение, не дожидаясь закрытия задачи

В нашем примере нужно выставить **«Да»** — чтобы сотрудник не мог уклониться от передачи дел.

---

### Как вставить динамическое значение в поле параметра

1. Нажать кнопку вставки значений рядом с нужным полем параметра
2. Откроется форма **«Вставка значений»**
3. Выбрать нужное значение из одного из блоков (см. раздел ниже)
4. Значение вставится в поле в виде конструкции `{...}` — это системный синтаксис подстановки

---

## Форма «Вставка значений» — детальный разбор

### Блоки доступных значений

#### 1. Параметры шаблона
- Значения, определённые разработчиком на уровне шаблона БП
- В типовых шаблонах могут быть пустыми — используются при создании шаблонов с нуля

#### 2. Переменные
- Временные переменные, объявленные разработчиком при создании БП
- Хранят промежуточные данные внутри процесса

#### 3. Константы
- Постоянные значения, заданные разработчиком в шаблоне
- Не меняются в ходе выполнения процесса

> Параметры шаблона, переменные и константы — **определяются разработчиком** при проектировании шаблона. Подробнее будет в следующих уроках.

#### 4. Поля документа
- Поля объекта, по которому запущен бизнес-процесс
- **Важная особенность:** отображаются только поля, **совместимые по типу** с параметром, в который вставляется значение

> **Пример из урока:**
> - Поле типа «Пользователь» (ответственный за задачу) → отображаются только поля документа типа «пользователь» (Кем создан, Кем изменён)
> - Поле типа «Текст» (название задачи) → отображаются все поля документа
> - Поле типа «Дата» (крайний срок) → отображаются только поля документа типа «дата»

#### 5. Дополнительные результаты
- Значения, «оставшиеся» после выполнения предыдущих действий в БП
- **Пример:** действие «Выбор сотрудника» сохраняет выбранного пользователя в временную переменную — здесь можно к ней обратиться
- Позволяет передавать данные между действиями в рамках одного БП

#### 6. Пользователи
- Выбор конкретного сотрудника из базы

#### 7. Категория пользователей
- Выбор группы сотрудников: отдел, группа, роль и т. д.

---

### Фильтрация по типу — ключевое поведение

Форма «Вставка значений» **автоматически фильтрует** доступные значения в зависимости от типа целевого поля:

| Тип параметра | Что отображается в «Полях документа» |
|---|---|
| Пользователь / Сотрудник | Только поля типа «пользователь» |
| Текст | Все поля |
| Дата | Только поля типа «дата» |

Это защита от некорректной подстановки — система не позволяет вставить дату туда, где ожидается имя пользователя.

---

### Синтаксис подстановки

После выбора значения оно вставляется в поле в виде:
```
{=Document:FIELD_CODE}
```
или аналогичной конструкции в фигурных скобках.

- Это не просто текст — это **инструкция для системы**
- В момент выполнения БП система заменяет эту конструкцию на реальное значение
- Можно комбинировать статический текст и вставленные значения в одном поле

> **Пример:** название задачи может быть: `Передача дел — {=Document:CREATED_BY} уходит в отпуск`

## Калькулятор

### Зачем нужен

Для полей, которые **нельзя взять напрямую** из документа или переменных, а нужно **вычислить**.

**Типичный пример:** крайний срок задачи.
- Нельзя просто взять дату из поля документа — нужно посчитать «дата согласования + 2 рабочих дня»
- Именно для этого используется калькулятор

### Возможности

- Арифметические операции (`2 + 2`, умножение, деление)
- Вычисления с датами (прибавить/вычесть дни, рабочие дни, часы)
- Использование значений из полей документа, переменных, результатов действий в формулах
- Широкий спектр функций — см. документацию

**Подход к освоению (из урока):**
> «Сначала учимся вычислять 2+2 :) — потом узнаём про море возможностей»

**Документация:** https://helpdesk.bitrix24.ru/open/5428897/

## Модификаторы

### Зачем нужны

Для **преобразования типа или формата** значения при его вставке.

### Типичные сценарии применения

- Преобразование типов: строка → число, число → строка, дата → строка определённого формата
- Форматирование: изменить формат отображения даты, числа
- Другие трансформации данных

### Как используются

Применяются при вставке значений — к вставляемому значению добавляется модификатор, который преобразует его перед подстановкой.

**Документация (таблица преобразований):** https://helpdesk.bitrix24.ru/open/5426411/

## Хорошие практики именования действий

> Из урока: «Когда вы создаёте и размещаете действия в бизнес-процессе, их явное именование поможет потом ориентироваться, чтобы вернуться к своим работам, понять, что у вас там происходило, и дорабатывать даже собственный бизнес-процесс через некоторое время»

**Правило:** давайте действиям понятные, описательные названия, отражающие суть того, что они делают. Это критично для:
- Поддержки и доработки шаблонов через время
- Работы в команде
- Отладки сложных шаблонов

## Главное

1. **Параметры действий могут быть динамическими.** Не нужно вписывать статические значения — можно подставить данные из документа, переменных или результатов других действий.

2. **Форма «Вставка значений» содержит 7 блоков:** параметры шаблона, переменные, константы, поля документа, дополнительные результаты, пользователи, категории пользователей.

3. **Тип поля определяет доступные значения.** Форма вставки автоматически фильтрует значения по совместимому типу — это защита от ошибок несовместимости данных.

4. **«Дополнительные результаты» — мост между действиями.** Если предыдущее действие что-то «вычислило» или «выбрало» (например, нашло руководителя), эти данные доступны в последующих действиях через этот блок.

5. **Значение вставляется как конструкция `{...}`.** В момент выполнения БП система заменяет её на реальные данные. Статический текст и динамические значения можно комбинировать в одном поле.

6. **Калькулятор нужен для вычисляемых значений.** Если нужно «дата + N дней» или любая другая формула — это калькулятор, а не просто вставка значения.

7. **Параметр «Остановить процесс» — инструмент контроля.** Если задаче нужно обязательно завершиться до продолжения процесса — ставьте «Да». Это создаёт «блокер» для движения вперёд.

8. **Модификаторы решают проблему несовместимости типов.** Если значение нужного типа нет, но есть в другом формате — используй модификатор для преобразования.

9. **Именуйте действия явно.** Понятные названия — это инвестиция в поддержку шаблонов в будущем, особенно в командной работе.

10. **Начинать осваивать параметры удобно через изменение типового шаблона.** Найди реальный процесс, добавь одно действие с динамическим параметром — это даёт быстрое понимание механики.
