# Модуль 3, Урок 6: Модификаторы — преобразование значений в читаемый вид

## О чём этот урок

Урок посвящён механизму **модификаторов** в бизнес-процессах Bitrix24 — инструменту, который преобразует технические системные значения (ID, коды) в читаемые, человекопонятные данные при подстановке в параметры действий. Без модификаторов пользователи видели бы в сообщениях и уведомлениях служебные идентификаторы вместо имён, дат и текстов. Понимание модификаторов критично для создания любых БП, которые отправляют уведомления или работают с пользовательскими данными.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Модификатор** | Преобразование, применяемое к вставляемому значению при подстановке в параметр действия; меняет тип данных или формат отображения |
| **Тип данных поля** | Каждое поле документа и каждая переменная БП имеют определённый тип: текст, число, дата, ID пользователя, ID элемента и т.д. |
| **`printable`** | Ключевой модификатор, преобразующий техническое/системное значение (например, ID пользователя) в его читаемое строковое представление (имя пользователя) |
| **Служебная переменная** | Переменная, хранящая внутренний идентификатор системы (например, числовой ID), а не отображаемое значение |
| **Читаемое значение** | Человекопонятный вид данных: имя пользователя вместо его ID, название статуса вместо числового кода и т.п. |
| **`createdby`** | Системное поле «Кем создан» — хранит ID пользователя, а не его имя; без модификатора в сообщении будет показан числовой ID |

---

## Проблема: технические значения вместо читаемых данных

### Суть проблемы

В Bitrix24 многие поля документов и переменные БП хранят **не текстовые значения**, а **системные идентификаторы**:

- Поле «Кем создан» (`createdby`) — хранит **числовой ID пользователя**, а не его имя
- Поле статуса — может хранить числовой код, а не название статуса
- Поле ответственного — ID, а не имя

Если просто вставить такое значение в текст уведомления через стандартную подстановку, пользователь получит сообщение вида:

```
Документ создан: 42
```

Вместо ожидаемого:

```
Документ создан: Иван Иванов
```

### Пример из урока

В транскрипции показан конкретный кейс:

1. В действие «Уведомления / Сообщения соцсети» добавлено поле `createdby` (кем создан) **без модификатора**
2. В аналогичное поле вставлено то же значение `createdby`, но **с модификатором `printable`**
3. После запуска БП пользователь видит **два разных результата** — служебное значение (малоинформативное) и читаемое имя

> «То есть первое это вообще-то малоинформативное сообщение для пользователя. Это универсистемная переменная, которая используется. А это уже читаемое значение. Кто этот самый пользователь.»

## Модификатор `printable`

### Назначение

`printable` — **основной модификатор для перевода в читаемый вид**. Применяется к любому полю или переменной, которая хранит техническое значение и должна отображаться как текст.

### Когда применять

- При использовании полей типа «Пользователь» в текстовых сообщениях
- При выводе значений справочников (хранят коды, нужны названия)
- При использовании любой переменной, о которой известно, что она хранит ID, а не текст
- Когда нужно убедиться, что значение будет отображаться корректно в уведомлении

### Как синтаксически применяется

Модификатор добавляется к стандартной конструкции вставки значения. Точный синтаксис описан в официальной документации:

**Документация по модификаторам:** https://helpdesk.bitrix24.ru/open/5426411/

Страница содержит:
- Таблицу преобразований типов данных (из какого типа → в какой тип)
- Описание всех доступных модификаторов
- Примеры применения

## Категории модификаторов (обзор по документации)

Помимо `printable`, существуют и другие модификаторы. Их можно разделить на группы:

| Группа | Что делают |
|---|---|
| **Преобразование типов** | Конвертируют значение из одного типа в другой (число → строка, дата → строка и т.п.) |
| **Форматирование** | Задают формат отображения (формат даты, количество знаков после запятой и пр.) |
| **Читаемый вид** | `printable` и аналоги — из системного в человекопонятное |
| **Работа с текстом** | Изменение регистра, обрезка, замена символов |

> Для базовой работы достаточно знать `printable`. Остальные модификаторы изучаются по мере необходимости из документации.

## Зачем нужны действия «Уведомления / Сообщения соцсети»

В уроке используется именно это действие для демонстрации, поскольку результат работы модификатора виден немедленно в интерфейсе Bitrix24 (в ленте новостей / уведомлениях). Это удобно для быстрой проверки.

**Структура действия в примере:**

| Параметр | Значение |
|---|---|
| Получатель сообщения | `createdby` — кем создан (системная переменная) |
| Текст сообщения (1) | `createdby` **без модификатора** — выведет ID |
| Текст сообщения (2) | `createdby` **с модификатором `printable`** — выведет имя |
| Дополнительно | Действие «Прерывание процесса» после — для изоляции теста |

## Пошаговые инструкции

### Применить модификатор к вставляемому значению

1. Открыть параметры нужного действия (например, «Уведомления / Сообщения соцсети»)
2. В нужном текстовом поле параметра вставить значение через форму «Вставка значений»
3. Найти нужное поле (например, «Кем создан» / `createdby`)
4. При вставке — найти пункт изменения модификатора (в форме вставки есть выбор модификатора)
5. Выбрать модификатор `printable`
6. Подтвердить вставку
7. Сохранить параметры действия

> Альтернативно: посмотреть синтаксис в документации (https://helpdesk.bitrix24.ru/open/5426411/) и дописать модификатор вручную к уже вставленному значению.

---

### Проверить работу модификатора (быстрый тест)

1. Убедиться, что шаблон БП настроен на **«Запуск при изменении»**
2. В тестовое действие «Сообщение» вставить **одно и то же поле дважды**:
   - Первая вставка — **без модификатора** (для сравнения)
   - Вторая вставка — **с модификатором `printable`**
3. Добавить действие **«Прерывание процесса»** сразу после тестового действия
4. Сохранить шаблон
5. Открыть тестовый документ → нажать «Применить» (или сохранить изменение)
6. Открыть уведомления/ленту — сравнить два значения
7. Первое должно показать системное ID, второе — читаемое имя

## Связь с другими темами урока

Модификаторы — часть более широкого набора инструментов работы с данными в БП:

```
Вставка значений
    └── Простая подстановка {Document:FIELD}
    └── С модификатором {Document:FIELD|printable}  ← тема этого раздела
    └── Через калькулятор {{=формула}}
         └── В формуле можно использовать поля документа
         └── Доступны функции (addworkdays, IF и т.д.)
```

Модификаторы и калькулятор — **разные инструменты для разных задач**:
- Модификатор — изменяет **формат/тип** существующего значения
- Калькулятор — **вычисляет** новое значение на основе формулы

## Главное

1. **Поля и переменные в БП имеют типы** — многие хранят не читаемый текст, а системные идентификаторы (ID пользователя, числовые коды). Это нормально, но нужно знать, с чем работаешь.

2. **Модификатор `printable` — решение в большинстве случаев.** Если в уведомлении вместо имени пользователя показывается число — нужен `printable`. Это самый часто используемый модификатор.

3. **Применяй модификатор при вставке значений, а не после.** Модификатор — часть синтаксиса подстановки; его нужно указать при вставке значения в поле параметра.

4. **Всегда сверяйся с таблицей модификаторов** (helpdesk.bitrix24.ru/open/5426411/). Там описаны все доступные преобразования и их синтаксис.

5. **Тестируй с двумя вставками рядом** — одна без модификатора, другая с `printable`. Это наглядно показывает разницу и подтверждает корректность применения.

6. **Без `printable` уведомления выглядят как системный лог.** Пользователи не должны видеть числовые ID — это плохой UX. Модификаторы — обязательный инструмент для production-качества БП.

7. **Действие «Остановить процесс» + «Сообщение» = изолированный тест.** Пара из этих двух действий позволяет быстро проверить любое значение/модификатор/формулу не запуская весь процесс.

8. **Модификаторы и Калькулятор — разные инструменты.** Модификатор меняет формат уже существующего значения; калькулятор вычисляет новое. В сложных формулах они могут использоваться совместно.

9. **Режим «Запуск при изменении» ускоряет разработку.** Не нужно создавать новый документ для каждой проверки — один и тот же документ можно «применять» снова и снова.

10. **Это один из базовых элементов любого нетривиального БП.** Почти каждый процесс, который работает с людьми (уведомляет, назначает, отправляет данные пользователям), требует корректного преобразования значений через модификаторы.
