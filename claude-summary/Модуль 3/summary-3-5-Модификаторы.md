# Модуль 3, Урок 6: Модификаторы — преобразование значений в читаемый вид

## О чём этот урок

Урок посвящён механизму **модификаторов** в бизнес-процессах Bitrix24 — инструменту, который преобразует технические системные значения (ID, коды) в читаемые, человекопонятные данные при подстановке в параметры действий. Без модификаторов пользователи видели бы в сообщениях и уведомлениях служебные идентификаторы вместо имён, дат и текстов.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Модификатор** | Преобразование, применяемое к вставляемому значению при подстановке в параметр действия; меняет тип данных или формат отображения |
| **Тип данных поля** | Каждое поле и переменная БП имеют тип: текст, число, дата, ID пользователя и т.д. |
| **`printable`** | Ключевой модификатор — преобразует техническое значение (ID пользователя) в его читаемое представление (имя пользователя) |
| **Служебная переменная** | Переменная, хранящая внутренний идентификатор системы, а не отображаемое значение |
| **`createdby`** | Поле «Кем создан» — хранит числовой ID пользователя; без модификатора в сообщении будет показан ID |

---

## Проблема: технические значения вместо читаемых

Многие поля документов хранят **не текст, а системные идентификаторы**:

- `createdby` — хранит числовой **ID пользователя**, не имя
- Поля справочников — хранят числовые коды, не названия

Без модификатора пользователь получит:
```
Документ создан: 42
```
Вместо ожидаемого:
```
Документ создан: Иван Иванов
```

> «Первое это вообще-то малоинформативное сообщение для пользователя. Это универсистемная переменная, которая используется. А это уже читаемое значение.»

---

## Модификатор `printable`

**Основной модификатор для перевода в читаемый вид.**

Когда применять:
- Поля типа «Пользователь» в текстовых сообщениях
- Значения справочников (код → название)
- Любая переменная, которая хранит ID, а не текст
- Везде, где нужно человекопонятное отображение в уведомлении

**Документация:** https://helpdesk.bitrix24.ru/open/5426411/

---

## Пошаговые инструкции

### Применить `printable` к значению

1. Открыть параметры нужного действия («Уведомления / Сообщения соцсети»)
2. В текстовом поле вставить значение через форму «Вставка значений»
3. При вставке — выбрать модификатор `printable`
4. Сохранить параметры

### Быстро проверить результат

1. Шаблон БП настроить на **«Запуск при изменении»**
2. В действие «Сообщение» вставить **одно поле дважды**: без модификатора и с `printable`
3. Добавить **«Прерывание процесса»** сразу после
4. Сохранить → открыть тестовый документ → «Применить»
5. В уведомлениях сравнить два значения: первое — системный ID, второе — читаемое имя

---

## Главное

1. **Многие поля хранят системные ID, а не текст** — это нормально, но нужно знать и применять модификаторы.
2. **`printable` — решение в большинстве случаев.** Число вместо имени в уведомлении → добавь `printable`.
3. **Без `printable` уведомления выглядят как системный лог** — плохой UX, недопустимо в production-БП.
4. **Таблица модификаторов** (helpdesk.bitrix24.ru/open/5426411/) — обязательный bookmark для разработчика БП.
5. **Тестируй двойной вставкой** — одно значение без модификатора, одно с `printable` рядом: сразу видна разница.
6. **Модификатор ≠ Калькулятор:** модификатор меняет формат существующего значения; калькулятор вычисляет новое.
7. **«Остановить процесс» + «Сообщение»** = изолированный стенд для быстрой проверки любого значения.
8. **Режим «Запуск при изменении»** — не создавай новый документ каждый раз, меняй один и тот же.
9. Модификаторы — **обязательный инструмент** для любого БП, который работает с пользователями и отправляет уведомления.
10. Понимание типов данных в полях Bitrix24 — **фундамент** для правильного применения модификаторов.
