# Бизнес-процессы в Битрикс24 — Процессы в ленте новостей

## О чём этот урок

Урок показывает, как работают «процессы в ленте» — особая сущность Bitrix24, позволяющая запускать бизнес-процессы прямо из живой ленты. На примере заявления на отпуск разбирается полный цикл согласования: от сотрудника через руководителя к бухгалтеру, с обсуждением прямо внутри процесса.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Процессы в ленте** | Сущность Bitrix24, представляющая табличные данные (список счетов, заявлений и т.д.) с возможностью запуска БП прямо из живой ленты |
| **Живая лента (лента новостей)** | Главная коммуникационная среда Bitrix24; место, где появляются уведомления о запущенных БП, задания участников и обсуждения |
| **Оргсхема компании** | Структура отделов и руководителей в Bitrix24; используется для автоматического определения участников процессов (например, руководителя сотрудника) |
| **Активные задания** | Централизованный раздел в «Бизнес-процессах», где собраны все текущие задания участника по всем запущенным процессам системы |
| **Этапы бизнес-процесса** | Последовательные шаги, через которые проходит процесс; система информирует о текущем этапе и ответственном |

---

## Что такое «процессы в ленте»

Раздел находится по пути: **Бизнес-процессы → Процессы в ленте**.

Это табличные данные — по сути, управляемые списки с заданной структурой полей. Каждая таблица — отдельный тип процесса:

- Счета на оплату
- Заявления на отпуск
- Заявления на командировку
- Любые другие (можно создавать свои)

Для каждого такого списка администратор сам определяет:
- **Какие поля** будут у записи (даты, суммы, комментарии, файлы и т.д.)
- **Какой бизнес-процесс** будет запускаться при создании записи

---

## Роль оргсхемы в автоматизации

Оргсхема — критический элемент для корректной работы автоматики.

Когда БП должен найти руководителя сотрудника, система берёт эту информацию из оргсхемы:

1. Определяет, в каком отделе находится сотрудник
2. Смотрит, кто назначен руководителем этого отдела
3. Автоматически направляет задание этому руководителю

> **Важно:** если оргсхема не заполнена или заполнена неверно, автоматика сработает неправильно. Перед настройкой БП необходимо корректно расставить сотрудников по отделам и назначить руководителей.

## Как работает БП «Заявление на отпуск» — полный цикл

### Участники процесса
| Роль | Действие |
|---|---|
| **Сотрудник** | Заполняет и отправляет заявление |
| **Руководитель** | Утверждает или отклоняет отпуск |
| **Бухгалтер** | Оформляет отпуск (начисляет отпускные, готовит документы) |

### Шаг 1 — Сотрудник запускает заявление
1. Войти в живую ленту под учётной записью сотрудника
2. Нажать **«Ещё» → «Процессы»**
3. Выбрать процесс **«Заявление на отпуск»**
4. Прочитать описание процесса (система показывает, что он заменяет бумажный документооборот)
5. Заполнить поля: **даты** отпуска, **комментарий** (опционально)
6. Нажать **«Отправить»**

### Шаг 2 — Уведомление в живой ленте
- В живой ленте сразу появляется карточка запущенного процесса
- Карточка содержит: имя сотрудника, следующий этап, кто ответственен
- Система автоматически определила руководителя по оргсхеме

### Шаг 3 — Руководитель согласует отпуск
- В живой ленте руководителя появляется **полноценная карточка задания** с:
  - Именем сотрудника
  - Датами отпуска
  - Комментарием
  - Кнопками действий: **«Утвердить»** / **«Отклонить»**
- Руководитель может **написать комментарий** прямо в карточке (как в обычном посте)
- После нажатия «Утвердить» — процесс переходит к следующему этапу

### Шаг 4 — Бухгалтер оформляет отпуск
- В живой ленте бухгалтера появляется задание **«Оформление отпуска»**
- Задание содержит: кому, от кого, что нужно сделать
- Кнопка для отметки выполнения: **«Отпуск оформлен»**
- Это задание также дублируется в разделе **Бизнес-процессы → Активные задания** — его можно найти и выполнить, не заходя в ленту

### Шаг 5 — Уведомление сотруднику о результате
- Сотрудник видит в своей ленте итоговое сообщение:
  - Заявление **одобрено**
  - Отпуск **оформлен**
- Полная информационная карточка с итогом всего процесса

## Пошаговые инструкции

### Запустить процесс из живой ленты

1. Открыть **Живую ленту** (главная страница портала или раздел «Лента»)
2. Нажать **«Ещё»** в поле создания записи
3. Выбрать **«Процессы»**
4. В списке найти нужный процесс (например, «Заявление на отпуск»)
5. Заполнить предложенные поля формы
6. Нажать **«Отправить»** / **«Запустить»**

### Выполнить задание по БП (два способа)

**Способ 1 — Из живой ленты:**
1. Найти карточку задания в ленте новостей
2. Ознакомиться с деталями прямо в карточке
3. Нажать кнопку действия (утвердить / отклонить / отметить выполненным)

**Способ 2 — Из раздела «Активные задания»:**
1. Перейти в **Бизнес-процессы → Активные задания**
2. Найти нужное задание в списке
3. Открыть и выполнить действие

> Оба способа равнозначны — используйте удобный в конкретный момент.

### Обсудить вопрос по запущенному процессу

1. Найти карточку процесса / задания в живой ленте
2. Нажать **«Комментировать»** (как в обычном посте ленты)
3. Написать сообщение — все участники процесса увидят его в своей ленте

## Преимущества процессов в ленте перед бумажным документооборотом

| Бумажный документооборот | Процессы в Bitrix24 |
|---|---|
| Нужно физически найти человека | Задание приходит автоматически в ленту |
| Человека может не быть на месте | Задание ждёт, уведомление приходит сразу |
| Нет истории согласования | Полная лента событий по процессу |
| Нет обсуждения в контексте документа | Комментарии прямо в карточке процесса |
| Сотрудник не знает статус своего заявления | Мгновенное уведомление на каждом этапе |

## Главное

1. **«Процессы в ленте»** — отдельная сущность Bitrix24; это управляемые таблицы (заявления, счета и т.д.) с встроенными бизнес-процессами, запускаемыми из живой ленты
2. **Запуск БП — через живую ленту**: путь «Ещё → Процессы» — стандартный способ для рядового сотрудника
3. **Оргсхема — основа автоматики**: система определяет руководителя по оргсхеме; без неё автоматическое назначение участников не работает
4. **Задания участников появляются в живой ленте** — не нужно искать их в отдельных разделах; достаточно зайти на портал
5. **Обсуждение — прямо в карточке процесса**: живая лента позволяет комментировать задание, как обычный пост
6. **Активные задания** — централизованный резервный интерфейс; все незавершённые задания по всем БП собраны в одном месте
7. **Сотрудник информирован на каждом этапе**: система показывает текущий статус, кто выполнил, кто ожидает — полная прозрачность процесса
8. **Поля форм настраиваемы**: администратор сам определяет, какие данные собирает тот или иной процесс (даты, суммы, файлы, комментарии и т.д.)
