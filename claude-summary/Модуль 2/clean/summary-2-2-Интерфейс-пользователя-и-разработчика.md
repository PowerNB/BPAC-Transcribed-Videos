# Интерфейс пользователя и разработчика

## О чём этот урок

Урок демонстрирует работу с бизнес-процессами в Bitrix24 с двух точек зрения:
- **Пользователь** — получает задания и выполняет их, не видя схему процесса
- **Разработчик** — видит и редактирует шаблон процесса в визуальном дизайнере

На практическом примере шаблона «Голосование за документ» показан полный цикл: запуск процесса → получение задания → выполнение действия → просмотр журнала истории.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Действие (Activity)** | Базовый элемент бизнес-процесса — один «кирпичик» в цепочке алгоритма. Может быть задачей, условием, уведомлением и т.д. Синонимы: «кубик», «элемент», «activity» (англ.) |
| **Дизайнер бизнес-процессов** | Визуальный редактор в Bitrix24, где разработчик видит схему процесса в виде блок-схемы и управляет действиями |
| **Раздел «Бизнес-процессы»** | Персональный раздел пользователя, где отображаются все задания, поступившие ему по запущенным процессам |
| **Журнал бизнес-процесса** | История всех шагов, выполненных в рамках конкретного экземпляра процесса |
| **Типовые (стандартные) бизнес-процессы** | Готовые шаблоны от Bitrix24, устанавливаемые из файлов диска (например, «Простое утверждение», «Голосование») |
| **Простое утверждение / Голосование** | Стандартный шаблон БП: документ утверждается, если большинство назначенных сотрудников проголосовало «за» |
| **Счётчик заданий** | Цифровой индикатор в разделе «Бизнес-процессы», показывающий количество ожидающих выполнения заданий |
| **Робот** | Упрощённый интерфейс для создания автоматизации, ориентированный на бизнес-пользователей. По сути — «обёртка» над стандартным бизнес-процессом, внутри устроен так же |

---

## Два режима работы с бизнес-процессами

### Режим пользователя

Пользователь **не видит схему процесса** — он видит только то, что ему нужно сделать прямо сейчас.

**Что доступно пользователю:**
- Раздел «Бизнес-процессы» — единое место для всех входящих заданий
- Счётчик новых заданий (цифра-индикатор на иконке раздела)
- Карточка задания: краткое описание, автор документа, что требуется сделать
- Визуализация цепочки: кто запустил процесс → кому переданы задания (повышает прозрачность)
- Ссылка на сам документ — можно открыть и ознакомиться прямо из задания
- Кнопки решения: **утвердить / отклонить** (или иное действие в зависимости от шаблона)

---

### Режим разработчика

Разработчик работает со шаблонами процессов и **видит всю схему целиком**.

**Что доступно разработчику:**
- Раздел «Бизнес-процессы» → **Шаблоны бизнес-процессов**
- Дизайнер бизнес-процессов — визуальный редактор в виде блок-схемы
- Список всех действий (Activity), из которых собран процесс
- Возможность добавлять, изменять и удалять действия в цепочке

---

## Стандартный шаблон «Простое утверждение / Голосование»

### Логика работы

1. Инициатор запускает БП на документе
2. Указывает сотрудников, которые должны проголосовать
3. Каждый сотрудник получает задание «Поголосуйте за документ»
4. Если большинство проголосовало «за» → статус документа становится **«Утверждён»**
5. История процесса сохраняется в журнале

### Где хранится история

> Карточка документа на диске → вкладка **«Бизнес-процессы»** → статус + кнопка **«Журнал»**

---

## Дизайнер бизнес-процессов — ключевые детали

- Представляет процесс в виде **визуализации алгоритма (блок-схемы)**
- Основной строительный блок — **Действие (Activity)**
  - Синонимы: «кубик», «кирпичик», «элемент», «activity» (англ.)
  - Специалисты Bitrix24 используют оба варианта: «действие» и «activity»
- Из действий складывается цепочка, реализующая логику конкретного процесса
- **Интерфейс дизайнера единый** для всех объектов — лидов, документов на диске, процессов в живой ленте. Блоки и логика одинаковы
- Подробный разбор всех типов действий — тема следующих уроков модуля

---

## Пошаговые инструкции

### 1. Запуск бизнес-процесса по файлу на диске

1. Открыть раздел **Диск** → найти нужный файл
2. В контекстном меню файла выбрать **«Бизнес-процессы»**
3. Выбрать шаблон (например, «Простое утверждение или голосование»)
4. Прочитать описание — система объяснит, что произойдёт
5. Указать сотрудников-участников
6. Нажать **«Запустить»**

---

### 2. Выполнение задания (от лица сотрудника)

1. Перейти в раздел **«Бизнес-процессы»** своего портала
2. Найти задание по счётчику или в списке
3. Ознакомиться с карточкой задания: автор, описание, что требуется
4. *(Опционально)* Нажать **«Перейти к документу»** — открыть и прочитать файл
5. Принять решение: **утвердить** или **отклонить**
6. Задание закрывается, результат уходит в процесс

---

### 3. Просмотр истории бизнес-процесса по документу

1. Открыть раздел **Диск** → найти нужный файл
2. Открыть подробности файла
3. Перейти на вкладку **«Бизнес-процессы»**
4. Увидеть список запущенных процессов и их статус (например, «Утверждён»)
5. Нажать **«Журнал»** — просмотреть полную цепочку событий

---

### 4. Просмотр шаблона в дизайнере (для разработчика)

1. Перейти в раздел **«Бизнес-процессы»** (административная часть)
2. Открыть **«Шаблоны бизнес-процессов»**
3. Найти нужный шаблон и открыть его
4. Откроется **Дизайнер бизнес-процессов** — визуальная схема-алгоритм
5. Изучить цепочку действий (Activity) — каждый блок это одно действие

---

## Главное

1. **Два интерфейса — два угла зрения.** Пользователь видит только задания, разработчик — полную схему процесса. Важно понимать оба режима.
2. **Раздел «Бизнес-процессы» — центр задач сотрудника.** Все задания по всем процессам собираются в одном месте, со счётчиком непрочитанных.
3. **Действие (Activity) — атомарный элемент любого БП.** Всё, что происходит в процессе, это цепочка действий в дизайнере. Синонимы: «кубик», «кирпичик», «activity».
4. **Стандартные шаблоны — быстрый старт.** «Простое утверждение/голосование» работает «из коробки» и хорошо иллюстрирует базовую механику БП.
5. **Журнал хранит полную историю.** Каждый запуск процесса логируется — можно отследить, кто что сделал и когда.
6. **Дизайнер — инструмент разработчика, не пользователя.** Рядовой сотрудник никогда не видит схему — он работает только с готовыми заданиями.
7. **Визуализация цепочки в задании повышает прозрачность.** Пользователь видит, кто запустил процесс и кому ещё назначено задание.
8. **Шаблоны устанавливаются из файлов диска** — это стандартный способ развернуть типовые процессы в новом портале.
9. **Робот — упрощённая обёртка над БП.** Внутри робот устроен так же, как полноценный бизнес-процесс, но интерфейс рассчитан на бизнес-пользователей без технических знаний.
10. **Дизайнер единый для всех объектов.** Одни и те же блоки и логика используются для лидов, документов на диске и процессов в живой ленте.
