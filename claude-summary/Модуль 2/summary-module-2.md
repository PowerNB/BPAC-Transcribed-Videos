# Модуль 2: Автоматизация бизнес-процессов в Bitrix24 — Итоговый обзор

## О модуле

Модуль посвящён автоматизации бизнес-процессов (БП) в Bitrix24: от базового понимания архитектуры системы до практической работы с конкретными объектами. Рассматривается, где и как существуют бизнес-процессы, как они запускаются и выглядят с точки зрения рядового сотрудника и разработчика. Центральная идея модуля — **единый дизайнер бизнес-процессов**, который работает одинаково для всех объектов системы: документов на Диске, процессов в живой ленте, сущностей CRM и заказов интернет-магазина. Освоив этот инструмент один раз, специалист применяет знания во всей системе. Модуль выстроен по принципу «от простого к сложному»: сначала Диск и лента новостей, затем полноценная CRM-автоматизация.

---

## Блок 1. Архитектура бизнес-процессов в Bitrix24

### Где доступны бизнес-процессы

Бизнес-процессы поддерживаются несколькими объектами системы:

| Объект | Что автоматизируется |
|---|---|
| **Диск** | Документы (файлы на общем диске) |
| **Живая лента** | Обсуждения, новости, процессы из ленты |
| **Списки в группах** | Элементы табличных списков |
| **CRM** | Лиды, сделки, контакты, компании |
| **Интернет-магазин** | Заказы |

### Доступность по тарифам

- **Бесплатный тариф** — бизнес-процессы недоступны
- **Платные тарифы** — включены
- **Демо-режим** — полный доступ на 30 дней, однократно для портала; оптимальный выбор для обучения

### Три инструмента автоматизации

```
Стадии воронки (CRM)
    ├── Роботы        — упрощённый интерфейс для бизнес-пользователей
    ├── Триггеры      — условия запуска роботов при наступлении событий
    └── Бизнес-процессы — полноценная схема: на создание / изменение / вручную
```

> Роботы и полноценные БП **не заменяют**, а **дополняют** друг друга.

## Блок 2. Дизайнер бизнес-процессов — единый инструмент

### Ключевой принцип

Дизайнер БП **единый для всех объектов** Bitrix24. Одни и те же блоки, одна и та же логика — для документов, ленты, CRM и магазина. Освоив его на простом примере, специалист работает с любым объектом системы без дополнительного обучения.

### Основной строительный блок — Действие (Activity)

- Атомарный элемент любого бизнес-процесса
- Синонимы: «кубик», «кирпичик», «activity» (англ.)
- Из действий складывается цепочка, реализующая логику процесса
- Типы действий (задача, условие, уведомление и др.) — предмет отдельных уроков курса

### Два режима работы с дизайнером

| Режим | Что видит |
|---|---|
| **Пользователь** | Только своё задание: что сделать, от кого, кнопки действий |
| **Разработчик** | Полную схему-алгоритм процесса, все действия, возможность редактирования |

### Где открыть дизайнер

- `Настройки объекта → Бизнес-процессы → Шаблоны → Открыть шаблон`
- Роботы CRM: `Настройка роботов → кнопка «Настройка» → Редактировать в дизайнере БП`

## Блок 3. Бизнес-процессы на Диске

### Активация (двухшаговая)

1. `Диск → Общий диск → Настройки раздела` — включить «Настройка бизнес-процессов»
2. Перейти в раздел «Бизнес-процессы» → установить стандартные шаблоны вручную

> ⚠️ Стандартные шаблоны **не устанавливаются автоматически** — нужно установить вручную.

### Запуск БП для файла

`Диск → контекстное меню файла → «Запустить бизнес-процесс» → выбрать шаблон`

### Стандартный шаблон «Простое утверждение / Голосование»

- Инициатор выбирает сотрудников для голосования
- Каждый получает задание «Поголосуйте за документ»
- Большинство голосов «за» → статус документа становится «Утверждён»
- История сохраняется: `карточка файла → вкладка «Бизнес-процессы» → «Журнал»`

## Блок 4. Процессы в ленте новостей

### Что такое «Процессы в ленте»

Управляемые таблицы (заявления, счета и т.д.) с заданной структурой полей и встроенным бизнес-процессом, который запускается прямо из живой ленты.

**Путь:** `Бизнес-процессы → Процессы в ленте`

**Примеры типов процессов:**
- Заявления на отпуск
- Заявления на командировку
- Счета на оплату
- Любые другие (создаются администратором)

### Оргсхема как основа автоматики

Система **автоматически определяет руководителя** сотрудника по оргсхеме компании и направляет задание нужному участнику.

> ⚠️ Без корректно заполненной оргсхемы автоматическое назначение участников не работает.

### Полный цикл «Заявление на отпуск»

```
Сотрудник заполняет форму в ленте
        ↓
Система автоматически определяет руководителя (по оргсхеме)
        ↓
Руководитель получает задание → утверждает / отклоняет (прямо в карточке ленты)
        ↓
Бухгалтер получает задание «Оформить отпуск»
        ↓
Сотрудник получает уведомление об итоге
```

### Как запустить процесс из ленты

`Живая лента → «Ещё» → «Процессы» → выбрать процесс → заполнить поля → «Отправить»`

## Блок 5. Автоматизация в CRM

### Три способа запуска БП в CRM

1. **На создание объекта** — автоматически при добавлении нового лида/сделки
2. **На изменение объекта** — автоматически при изменении данных
3. **Вручную** — через контекстное меню объекта в списке

### Роботы в CRM

- Привязаны к **стадиям воронки**
- Упрощённый интерфейс, ориентированный на бизнес-пользователей
- Внутри устроены **так же, как полноценный БП**
- Открываются и редактируются в полноценном дизайнере

### Шаблоны БП для ручного запуска

`CRM → Настройки → Бизнес-процессы → выбрать сущность → Список шаблонов`

В списке лидов/сделок: контекстное меню строки → «Запустить бизнес-процесс»

---

## Блок 6. Пользовательский интерфейс: работа с заданиями

### Раздел «Бизнес-процессы» — центр задач сотрудника

- Единое место для всех входящих заданий по всем процессам системы
- Счётчик непрочитанных заданий (цифровой индикатор)
- Карточка задания: описание, автор, ссылка на документ, кнопки действий
- Визуализация цепочки: кто запустил → кому назначено (прозрачность)

### Два равнозначных способа выполнить задание

| Способ | Путь |
|---|---|
| Из живой ленты | Найти карточку задания → нажать кнопку действия |
| Из раздела задания | `Бизнес-процессы → Активные задания` → открыть → выполнить |

### Журнал истории

Каждый запуск процесса полностью логируется. История доступна:
- Для документов: `карточка файла → вкладка «Бизнес-процессы» → «Журнал»`
- Для процессов CRM: через карточку объекта

## Связи между темами модуля

```
Видео 1 (Запуск стандартных процессов)
    → Закладывает понимание объектов и тарифов
    → Вводит понятие шаблонов и активации БП

Видео 2 (Интерфейс пользователя и разработчика)
    → Показывает, как те же шаблоны (Диск) выглядят с двух сторон
    → Вводит понятие Действия (Activity) — базу дизайнера

Видео 3 (Процессы в ленте)
    → Применяет дизайнер к новому объекту (лента)
    → Добавляет оргсхему как источник данных для автоматики
    → Показывает многошаговый цикл согласования

Видео 4 (Автоматизация в CRM)
    → Объединяет всё: дизайнер + роботы + триггеры + стадии
    → Показывает наиболее сложную зону автоматизации
    → Замыкает стратегию «от простого к сложному»
```

## Ключевые выводы модуля

1. **Бизнес-процессы работают для множества объектов** — Диск, лента новостей, CRM (лиды, сделки, контакты, компании) и интернет-магазин (заказы). Принцип везде единый.
2. **Дизайнер бизнес-процессов — единый инструмент.** Одни и те же блоки и логика применяются ко всем объектам системы: освоив его один раз, применяешь везде.
3. **Действие (Activity) — атомарный строительный блок.** Любой бизнес-процесс — это цепочка действий. Понимание этого принципа — основа всей разработки БП.
4. **Стандартные шаблоны не устанавливаются автоматически** — их необходимо установить вручную. Активация БП на Диске — двухшаговая процедура.
5. **Два интерфейса — два угла зрения:** пользователь видит только своё задание, разработчик — полную схему. Важно понимать оба режима при проектировании процессов.
6. **Оргсхема компании — критически важный элемент** для корректной работы автоматического назначения участников. Без неё автоматика не работает.
7. **Живая лента — единая среда коммуникации и управления.** Задания появляются прямо в ленте, там же можно их обсуждать и выполнять — без перехода в другие разделы.
8. **Раздел «Бизнес-процессы» — центр задач сотрудника.** Все задания по всем процессам системы собраны в одном месте со счётчиком непрочитанных.
9. **Робот — упрощённая обёртка над полноценным БП.** Внутри устроен одинаково, но интерфейс рассчитан на бизнес-пользователей; открывается и редактируется в том же дизайнере.
10. **Роботы, триггеры и полноценные БП дополняют друг друга**, а не заменяют. В CRM все три инструмента работают параллельно и в связке со стадиями воронки.
11. **Журнал хранит полную историю** каждого запущенного процесса — кто, что и когда выполнил. Это инструмент контроля и прозрачности.
12. **БП в CRM запускаются тремя способами:** автоматически на создание объекта, автоматически на изменение, и вручную через контекстное меню.
13. **Демо-режим (30 дней)** — оптимальный инструмент для изучения БП: бесплатно, полный доступ, однократно на портал. Рекомендуется зарегистрировать отдельный учебный портал.
14. **Стратегия обучения «от простого к сложному»** — принципиальна: сначала Диск и лента (простые объекты), затем CRM (сложная автоматизация с воронкой, роботами и триггерами).
15. **Прозрачность процесса — встроенная функция системы:** сотрудник видит статус на каждом этапе, цепочку участников и итоговый результат без дополнительных запросов к руководству.
