# Добавление значения в массив

## О чём этот урок

Урок посвящён работе с множественными значениями (массивами) в бизнес-процессах Bitrix24. Рассматривается конкретная задача: вместо того чтобы перезаписывать одну ссылку на заявку в карточке поставщика, нужно **накапливать** все заявки — добавлять новую ссылку к уже существующим. Для этого используется специальная функция `merge` из документации Bitrix24.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Массив** | Множественное значение поля — список из нескольких элементов (например, несколько ссылок на заявки) |
| **Функция `merge`** | Встроенная функция вычисления значений в Bitrix24, объединяющая элемент или массив с другим элементом/массивом |
| **Параметр бизнес-процесса** | Переменная, передаваемая при запуске БП (в данном случае — ссылка на текущую заявку) |
| **Поле документа** | Значение поля текущего объекта, с которым работает БП (например, текущее содержимое поля «Заявки» у поставщика) |
| **`document.property`** | Обращение к полю текущего объекта/документа внутри формулы |
| **`template.переменная`** | Обращение к параметру (переменной) текущего бизнес-процесса |

---

## Проблема: перезапись вместо накопления

### Что происходило без изменений

- При запуске БП поставщику присваивалась **одна** ссылка на заявку — та, которая была передана параметром.
- При повторном запуске БП с тем же поставщиком из **другой** заявки — предыдущая ссылка **перезаписывалась**.
- В итоге у поставщика всегда хранилась только **последняя** заявка, а не все.

### Желаемое поведение

- Поле «Заявки» у поставщика — **множественное** (так и было настроено изначально).
- Нужно не заменять значение, а **добавлять** новую ссылку к уже существующим.
- Цель: хранить ссылки **на все заявки**, в которых поставщик использовался.

---

## Решение: функция `merge`

### Где найти функцию

Функция описана в **официальной справке Bitrix24** в статье о вычислении значений. Путь: документация → статья по вычислению значений → раздел функций для работы с массивами.

### Синтаксис функции

```
merge(массив_1, массив_2_или_элемент)
```

- Объединяет два аргумента как элементы массива или как два массива.
- Если один из аргументов уже является массивом, а второй — одиночным значением, то одиночное значение **добавляется** в массив.

### Формула для накопления заявок

```
merge({document.property.заявки}, {template.заявка})
```

| Часть формулы | Что означает |
|---|---|
| `{document.property.заявки}` | Текущее значение поля «Заявки» у элемента поставщика (то, что уже там есть) |
| `{template.заявка}` | Параметр БП — ссылка на новую заявку, переданная при запуске |

**Логика:** берём то, что уже хранится у поставщика в поле «Заявки», и добавляем к нему новую заявку.

## Пошаговая инструкция: настройка накопления значений

### Шаг 1 — Открыть действие изменения элемента поставщика

1. Войти в редактор бизнес-процесса для **Заявок**.
2. Найти действие, которое **сохраняет значение заявки** в элемент поставщика.
3. Открыть настройки этого действия.

### Шаг 2 — Изучить текущую конфигурацию

- Сейчас в поле «Заявки» у поставщика просто **присваивается** значение параметра `{template.заявка}`.
- Это и есть причина перезаписи.

### Шаг 3 — Обратиться к документации

1. Открыть официальную документацию Bitrix24.
2. Найти статью о **вычислении значений** (Поддержка 24).
3. Найти описание функции `merge` и скопировать пример её вызова.

### Шаг 4 — Составить формулу

Собрать формулу из трёх частей:
1. Функция `merge(...)`.
2. Первый аргумент — **поле документа**: значение поля «Заявки» текущего элемента поставщика → `{document.property.заявки}`.
3. Второй аргумент — **параметр БП**: переданная заявка → `{template.заявка}`.

Итоговая формула:
```
merge({document.property.заявки}, {template.заявка})
```

### Шаг 5 — Вставить формулу в настройки действия

1. В поле настройки значения «Заявки» заменить простое присвоение на формулу с `merge`.
2. Сохранить действие и бизнес-процесс.

### Шаг 6 — Проверить результат

1. Перейти в **список поставщиков** — запомнить текущее состояние (например, у «ООО Мебель» одна заявка — «Карандаш для доски»).
2. Перейти в **Заявки** и запустить БП для другой заявки (например, «Новый стол»), выбрав того же поставщика — «ООО Мебель».
3. Вернуться в **список поставщиков** и обновить страницу.
4. Убедиться, что у «ООО Мебель» теперь **две ссылки** на заявки.

---

## Результат из урока

До изменения: у поставщика «ООО Мебель» — одна заявка («Карандаш для доски»).

После добавления `merge` и запуска БП из заявки «Новый стол»: у поставщика «ООО Мебель» — **две заявки**. Накопление работает корректно.

---

## Главное

1. **Простое присвоение перезаписывает** — если нужно накапливать данные в множественном поле, присвоение не подходит.
2. **Функция `merge`** — ключевой инструмент для добавления значения в массив без уничтожения предыдущих данных.
3. **Формула строится из двух частей**: текущее содержимое поля (`document.property`) + новое значение из параметра БП (`template.переменная`).
4. **Поле должно быть множественным** — это настраивается при создании поля в списке; только тогда накопление имеет смысл.
5. **Документация Bitrix24** по вычислению значений — обязательный ресурс при работе с нестандартными операциями над данными; функция `merge` описана именно там.
6. **Параметр БП** (`template.заявка`) и **поле документа** (`document.property.заявки`) — два разных источника данных, которые важно различать при составлении формул.
7. Такой подход позволяет строить **историю взаимодействий**: хранить у поставщика все заявки, у клиента — все сделки, и т.д.
