# Модуль 5, Урок 10: Параметры БП и работа с элементами списков

## О чём этот урок

Урок посвящён расширенным возможностям бизнес-процессов в Bitrix24: запуску БП с параметрами, запуску одного бизнес-процесса из другого, а также работе с элементами списков — их созданию, чтению и изменению прямо внутри бизнес-процесса. Эти инструменты позволяют строить гибкие сценарии автоматизации, не ограничиваясь данными одного документа.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Параметр бизнес-процесса** | Переменная, значение которой запрашивается у пользователя при ручном запуске БП или передаётся из другого бизнес-процесса при программном запуске |
| **Запуск БП с параметрами** | Сценарий, при котором перед стартом бизнес-процесса система показывает форму для ввода данных пользователем |
| **Запуск БП из БП** | Механизм, позволяющий одному бизнес-процессу инициировать выполнение другого, передавая ему данные через параметры |
| **Список (Процесс в Живой ленте)** | Отдельная сущность в Bitrix24, аналог справочника; хранит структурированные данные (например, список поставщиков) |
| **Привязка к элементам** | Тип поля/параметра в Bitrix24, позволяющий ссылаться на элемент конкретного списка или CRM-объекта |
| **Создание элемента списка** | Действие внутри БП, автоматически добавляющее новую запись в указанный список |
| **Изменение элемента списка** | Действие внутри БП, обновляющее поля существующего элемента списка без запуска отдельного бизнес-процесса |
| **Чтение элемента списка** | Действие внутри БП, получающее данные из конкретного элемента списка для дальнейшего использования в условиях или записях |
| **Добавление значения в массив** | Операция внутри БП, расширяющая переменную-массив новым значением |
| **Лог бизнес-процесса** | Журнал событий и действий, выполненных в ходе работы БП; используется для отладки и контроля |

---

## Раздел 1. Параметры запуска бизнес-процесса

### Зачем нужны параметры

- Параметры позволяют **запрашивать у пользователя данные в момент запуска** БП вместо того, чтобы жёстко фиксировать значения внутри процесса.
- Применяются в двух основных сценариях:
  1. **Ручной запуск** — пользователь заполняет форму с параметрами перед стартом.
  2. **Запуск из другого БП** — параметры передаются автоматически из родительского процесса.

### Типы параметров

- Параметры могут иметь те же типы, что и поля в Bitrix24:
  - Строка, число, дата и т.д.
  - **Привязка к элементам** — ссылка на запись конкретного списка (используется в примере урока для поля «Поставщик»).
- Параметры настраиваются как **обязательные** или **необязательные**.
- Параметры могут быть **единичными** или **множественными** (массив значений).

### Практический пример из урока

> Задача: дать пользователю возможность указывать и изменять поставщика в заявке, даже после её согласования (когда прямое редактирование заявки уже недоступно).
>
> Решение: создать отдельный бизнес-процесс с параметром «Поставщик» и запускать его вручную по необходимости.

## Раздел 2. Подготовка инфраструктуры — список «Поставщики»

### Зачем создавать отдельный список

- Поставщик оформляется как **отдельный процесс (список) в Живой ленте**, а не просто как текстовое поле.
- Это позволяет:
  - Хранить расширенные данные о каждом поставщике.
  - Использовать данные поставщика в условиях и действиях внутри БП.
  - Создавать и изменять поставщиков прямо из бизнес-процессов.

### Шаги по созданию списка «Поставщики»

1. Перейти в **Живую ленту** → создать новый процесс.
2. Назвать его **«Поставщики»**.
3. Настроить доступ: **чтение — для всех** (минимально необходимые права).
4. Добавить несколько тестовых элементов (записей поставщиков) — для тестирования БП.

### Добавление поля «Поставщик» в список заявок

1. Открыть настройки списка **«Заявки»**.
2. Добавить новое поле:
   - **Тип поля:** Привязка к элементам.
   - **Источник:** список «Поставщики» (указать конкретный процесс).
   - Остальные настройки — по умолчанию.
3. Сохранить поле.
4. Настроить **отображение нового поля** в представлении списка заявок.

## Раздел 3. Создание бизнес-процесса с параметром для Живой ленты

### Создание параметра БП

1. Открыть редактор бизнес-процесса для списка **«Заявки»**.
2. Перейти в раздел **«Параметры»** и добавить новый параметр:
   - **Название:** Поставщик (или аналогичное).
   - **Тип:** Привязка к элементам.
   - **Обязательность:** Необязательный *(важно — см. логику ниже)*.
   - **Множественность:** Нет (единичное значение).
   - **Источник привязки:** Процесс «Поставщики» в Живой ленте.
3. Сохранить параметр.

> **Почему параметр необязательный?**
> Автор сознательно делает параметр необязательным, добавляя внутри БП условие проверки: если значение указано — выполняем действие, если нет — пропускаем. Это подготовка к дальнейшим доработкам (в том числе к сценарию создания нового поставщика). Альтернатива — сделать параметр обязательным, тогда БП не запустится без его заполнения.

### Логика бизнес-процесса

```
СТАРТ
  │
  ├─ Условие: параметр «Поставщик» заполнен?
  │     │
  │     ├─ ДА → Записать значение параметра в поле «Поставщик» заявки
  │     │         └─ Записать событие в лог БП
  │     │
  │     └─ НЕТ → (ничего не делать / переход к следующим шагам)
  │
КОНЕЦ
```

### Настройка запуска

- Бизнес-процесс запускается **только вручную** (не автоматически).
- При запуске система отображает форму с параметром для заполнения.

### Проверка работы

1. Открыть элемент списка «Заявки».
2. Запустить созданный бизнес-процесс вручную.
3. Система показывает форму — **указать поставщика**.
4. После подтверждения — БП отрабатывает, в поле «Поставщик» заявки появляется выбранное значение.

## Раздел 4. Запуск бизнес-процесса из бизнес-процесса

### Концепция

- Один бизнес-процесс может **инициировать запуск другого БП**.
- Данные передаются через **параметры** запускаемого БП.
- Применение: когда нужно выполнить действия над **другим документом/объектом**, не доступным напрямую из текущего БП.

### Практический пример

> Из БП для «Заявок» запустить БП для «Поставщиков», передав туда нужные данные через параметры.

### Шаги реализации

1. **Создать бизнес-процесс для списка «Поставщики»**:
   - Добавить параметры, которые будут принимать данные от родительского БП.
   - Описать логику обработки (например, обновление данных поставщика).

2. **В бизнес-процессе «Заявок»** добавить действие **«Запуск бизнес-процесса»**:
   - Указать целевой список — «Поставщики».
   - Указать элемент, для которого запускается БП (например, выбранный поставщик из параметра).
   - Сопоставить параметры: какие значения из текущего БП передаются в параметры запускаемого БП.

3. Сохранить и протестировать цепочку.

### Ключевые моменты

- Через запуск БП из БП можно **передавать данные** между разными списками и объектами.
- Это мощный инструмент интеграции процессов внутри Bitrix24.

## Раздел 5. Добавление значения в массив

### Концепция

- В бизнес-процессах существует возможность работать с **массивами** (множественными значениями).
- Действие **«Добавить значение в массив»** позволяет динамически наполнять переменную-массив в ходе выполнения БП.

### Когда применять

- Когда нужно собрать несколько значений (например, список согласующих, несколько поставщиков и т.д.) перед тем, как передать их в следующее действие.
- Полезно при итерационной обработке данных.

---

## Раздел 6. Создание элемента списка из бизнес-процесса

### Концепция

- БП может **автоматически создавать новые записи** в любом доступном списке.
- Применение в данном уроке: пользователь может указать не только существующего поставщика, но и **нового** — БП сам создаст для него запись в списке «Поставщики».

### Логика расширенного сценария

```
При запуске БП:
  ├─ Пользователь выбирает существующего поставщика → записать в поле заявки
  └─ Пользователь указывает нового поставщика (имя/данные)
       └─ БП создаёт новый элемент в списке «Поставщики»
            └─ Полученный ID нового элемента записывается в поле «Поставщик» заявки
```

### Действие «Создание элемента списка»

- Указывается **целевой список** (например, «Поставщики»).
- Заполняются **поля нового элемента** — значениями из параметров БП или переменных.
- Результат действия — **ID созданного элемента**, который можно использовать дальше в процессе.

---

## Раздел 7. Изменение элемента списка из бизнес-процесса

### Концепция

- БП может **изменять поля существующих элементов** любого доступного списка напрямую, **без запуска отдельного бизнес-процесса** для этого элемента.
- Это более простой способ передать данные в другой элемент по сравнению со схемой «запуск БП из БП».

### Практический пример из урока

> Задача: сохранить в карточке поставщика информацию о **сумме последней заявки**, связанной с ним.

### Действие «Изменение элемента списка»

- Указывается **целевой список** и **конкретный элемент** (по ID или через привязку).
- Указываются **поля для обновления** и их новые значения (из переменных текущего БП).
- Изменения применяются немедленно при выполнении этого шага БП.

### Преимущество подхода

- Не требует создания дополнительного БП для целевого элемента.
- Прямая и быстрая передача данных между документами.

---

## Раздел 8. Чтение элемента списка из бизнес-процесса

### Концепция

- БП может **получать (читать) данные** из элемента любого списка и использовать их:
  - В условиях (ветвлении логики).
  - В действиях (подстановка значений).
  - В уведомлениях и записях.

### Практический пример из урока

> Получить данные о выбранном поставщике (из списка «Поставщики») и добавить условия в БП, которые работают с этими данными.

### Действие «Чтение элемента списка»

- Указывается **целевой список** и **элемент** для чтения (например, поставщик, выбранный в параметре).
- После выполнения действия **все поля элемента становятся доступны** как переменные внутри БП.
- Эти переменные можно использовать в последующих условиях и действиях.

### Расширение логики БП с использованием данных поставщика

```
Читаем данные выбранного поставщика
  │
  ├─ Условие А: значение поля X поставщика = «...» → выполнить действие 1
  ├─ Условие Б: значение поля Y поставщика > N → выполнить действие 2
  └─ Иначе → стандартный путь
```

## Пошаговые инструкции

### Инструкция 1. Создать список «Поставщики» и добавить поле в «Заявки»

1. Войти в **Живую ленту** → **Добавить новый процесс (список)** → назвать «Поставщики».
2. Настроить права доступа: всем — **чтение**.
3. Добавить несколько тестовых элементов в список.
4. Перейти в настройки списка **«Заявки»** → **Поля** → **Добавить поле**.
5. Тип поля — **Привязка к элементам**, источник — **Поставщики**.
6. Сохранить поле и настроить его отображение в списке.

---

### Инструкция 2. Создать параметр бизнес-процесса

1. Открыть редактор нужного БП.
2. Перейти в раздел **«Параметры»** → **«Добавить параметр»**.
3. Заполнить:
   - Название параметра.
   - **Тип:** Привязка к элементам.
   - **Обязательный:** нет (или да — по логике процесса).
   - **Множественный:** нет.
   - **Источник:** указать нужный список/процесс.
4. Сохранить параметр.

---

### Инструкция 3. Использовать параметр внутри БП

1. Добавить **условие** в схему БП: проверить, заполнен ли параметр.
2. На ветке «ДА» добавить действие **«Изменить элемент»** текущего документа.
3. В поле «Поставщик» документа подставить значение из параметра.
4. Добавить запись в **лог БП** для отслеживания.
5. Сохранить и опубликовать БП.
6. Протестировать: запустить вручную → заполнить параметр → проверить обновление поля.

---

### Инструкция 4. Прочитать элемент списка в БП

1. В схеме БП добавить действие **«Прочитать элемент списка»** (или аналогичное название в интерфейсе).
2. Указать:
   - Целевой **список** (например, «Поставщики»).
   - **Элемент** для чтения — выбрать из переменной (например, из параметра «Поставщик»).
3. После действия — все поля элемента доступны как **переменные БП**.
4. Использовать эти переменные в последующих **условиях** и **действиях**.

---

### Инструкция 5. Изменить элемент другого списка в БП

1. В схеме БП добавить действие **«Изменить элемент списка»**.
2. Указать целевой **список** и **элемент** (по ID или привязке).
3. Задать **поля для обновления** и их новые значения (из переменных текущего БП).
4. Сохранить действие — изменение применится при выполнении этого шага.

---

## Главное

1. **Параметры БП** — универсальный инструмент для получения данных от пользователя при ручном запуске или из другого бизнес-процесса при программном запуске.

2. **Тип параметра «Привязка к элементам»** позволяет ссылаться на записи любого списка или CRM-объекта — это ключевой инструмент для работы со связанными данными.

3. **Необязательный параметр + условие внутри БП** — гибкий паттерн: позволяет обрабатывать как заполненные, так и незаполненные данные в одном процессе, без жёсткого требования к пользователю.

4. **Запуск БП из БП с передачей параметров** — мощный способ реализовать межпроцессное взаимодействие и обрабатывать данные разных объектов в рамках единой автоматизации.

5. **Изменение элемента списка** — более простая альтернатива «запуску БП из БП» в тех случаях, когда нужно просто обновить поля другого документа без сложной логики.

6. **Чтение элемента списка** открывает возможность строить условия и действия на основе данных **связанных объектов**, а не только текущего документа.

7. **Создание элемента списка** прямо из БП позволяет реализовать сценарии «создай новое, если нужного ещё нет» без ручного вмешательства пользователя.

8. **Лог бизнес-процесса** — обязательный элемент для отладки: фиксируйте ключевые события, чтобы понимать, какая ветка сработала и какие данные были обработаны.

9. **Список как справочник** — выносить сущности (поставщики, категории и т.д.) в отдельные списки правильнее, чем хранить их как текстовые поля: это открывает возможности для чтения, изменения и создания записей из бизнес-процессов.

10. **Ограничения прав редактирования** можно обходить через **отдельный БП с параметрами**: пользователь не может редактировать заявку напрямую, но может запустить специальный процесс, который обновит нужное поле — это безопасный и контролируемый способ управления данными.
