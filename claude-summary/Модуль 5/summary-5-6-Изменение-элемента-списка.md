# Изменение элемента списка (Модуль 5, Урок 10)

## О чём этот урок

Урок посвящён работе с элементами списков внутри бизнес-процесса Bitrix24: как читать данные из
других документов и записывать значения в их поля. Это позволяет синхронизировать данные между
разными сущностями (заявки, поставщики, CRM-объекты) без ручного ввода. Конкретный пример урока —
автоматическое сохранение суммы последней заявки в карточку поставщика.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Элемент списка** | Запись в пользовательском списке Bitrix24 (например, строка в списке «Поставщики») |
| **Изменение элемента** | Действие в дизайнере БП, записывающее новые значения в поля уже существующего элемента |
| **ID элемента** | Уникальный идентификатор конкретной записи в списке — ключевой параметр для определения, _куда_ писать |
| **Тип документа** | Указывает, с каким списком/сущностью работает действие (например, «Поставщики», «Заявки») |
| **Параметры шаблона** | Переменные бизнес-процесса, передаваемые при запуске — могут использоваться как источник значений |
| **Поле документа** | Конкретное поле элемента, в которое будет записано значение (например, «Сумма последней заявки») |

---

## Действие «Изменение элемента списка»

### Что делает

Позволяет из бизнес-процесса **записать значение в поле уже существующего элемента** другого
(или того же) списка — без ручного редактирования и без запуска отдельного бизнес-процесса.

### Где применяется

- Запись данных в **элемент того же списка**, с которым работает БП
- Запись данных в **элемент другого списка** (например, из «Заявок» — в «Поставщиков»)
- Запись данных в **объекты CRM** (принцип тот же)

---

## Параметры действия «Изменение элемента»

### Обязательные параметры

1. **ID элемента** *(самый важный)*
   - Определяет конкретную запись, которую нужно изменить
   - Источник: параметр шаблона, переменная БП, результат другого действия
   - В примере урока: ID берётся из параметра шаблона «Поставщик» (выбранный пользователем)

2. **Тип документа**
   - Указывает, в каком списке/сущности находится элемент
   - Пример из урока: тип «Поставщики» — система должна понять, с какой сущностью ведётся работа
   - После выбора типа становятся доступны поля этой сущности

### Поля для заполнения

После указания типа документа система показывает список доступных полей элемента.  
Для каждого поля указывается **источник значения**:

| Источник | Пример |
|---|---|
| Поле текущего документа | `Поле от документа → Сумма` |
| Параметр шаблона | `Параметры шаблона → Поставщик` |
| Константа (вручную) | Фиксированное значение |
| Результат другого действия | Выход предыдущего шага БП |

## Пошаговая инструкция: запись суммы заявки в карточку поставщика

> **Сценарий:** Пользователь запускает БП согласования заявки. В параметре «Поставщик» он указывает
> существующего поставщика. БП автоматически записывает сумму заявки в поле «Сумма последней заявки»
> карточки этого поставщика.

**Шаг 1.** Открыть дизайнер бизнес-процесса для списка «Заявки».

**Шаг 2.** Добавить действие **«Изменение элемента»** в нужное место цепочки.

**Шаг 3.** Указать **ID элемента:**
- Источник — `Параметры шаблона → Поставщик`
- (Пользователь выбирает поставщика при запуске БП, его ID передаётся как параметр)

**Шаг 4.** Указать **тип документа:**
- Выбрать `Поставщики` (нужный список)
- После выбора система подгружает поля этой сущности

**Шаг 5.** Указать **поле для записи:**
- Поле: `Сумма последней заявки`
- Источник значения: `Поле от документа → Сумма`
- (Берём значение поля «Сумма» из текущей заявки)

**Шаг 6.** Нажать **«Сохранить»**.

**Шаг 7.** Сохранить и опубликовать бизнес-процесс.

### Проверка результата

После запуска БП с заявкой на сумму **5 000 ₽**:
- Открыть карточку выбранного поставщика в списке «Поставщики»
- Убедиться, что в поле **«Сумма последней заявки»** появилось значение `5000`

## Важные нюансы

- **Действие работает с _существующими_ элементами** — для создания нового элемента используется
  отдельное действие «Создание элемента списка» (рассматривается в этом же уроке)
- **Тип документа влияет на список доступных полей** — без его указания поля недоступны
- **ID элемента — критически важен:** если ID неверный или пустой, действие не знает, что изменять
- **Не требует запуска отдельного БП** — это более простой способ передать данные в другой элемент
  по сравнению с «запуском БП из БП»

---

## Главное

1. **Действие «Изменение элемента»** позволяет писать данные в любой список или CRM-объект прямо
   внутри бизнес-процесса — без ручного редактирования.

2. **ID элемента — ключевой параметр:** именно он определяет, в какую запись будут записаны данные.
   Чаще всего берётся из параметра шаблона или переменной БП.

3. **Тип документа обязателен:** без него система не знает, в каком списке искать элемент и какие
   поля ему доступны.

4. **Источник значения гибкий:** можно писать поля текущего документа, константы, параметры шаблона
   или результаты других действий.

5. **Это альтернатива «запуску БП из БП»:** когда нужно просто обновить данные в другом элементе,
   «Изменение элемента» — более простое и прямолинейное решение.

6. **Работает между разными списками:** из «Заявок» можно писать в «Поставщиков», из «Поставщиков»
   в CRM-контакты и т.д. — направление произвольное.

7. **Сценарий «накопление истории»:** поле «Сумма последней заявки» у поставщика — типовой пример
   использования для хранения агрегированных/актуальных данных из связанных документов.
