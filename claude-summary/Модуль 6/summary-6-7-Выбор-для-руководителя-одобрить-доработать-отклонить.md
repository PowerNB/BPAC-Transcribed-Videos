# Выбор для руководителя: одобрить, доработать, отклонить

## О чём этот урок

Урок посвящён расширению возможностей согласования в бизнес-процессе «Со статусами»: вместо двух вариантов («Одобрить» / «Отклонить») руководитель получает три — «Одобрить», «Доработать» и «Отклонить». Это позволяет реализовать более гибкое согласование заявок на портале Bitrix24 без лишних итераций. Урок показывает, как заменить стандартное действие «Утверждение документа» на более гибкое — «Запрос дополнительной информации» — и построить разветвлённую логику обработки каждого из трёх вариантов.

---

## Основные понятия

| Термин | Определение |
|---|---|
| **Бизнес-процесс «Со статусами»** | Тип БП в Bitrix24, в котором документ последовательно переходит между заданными статусами; в отличие от «Последовательного», позволяет возвращать документ на предыдущие этапы |
| **Действие «Утверждение документа»** | Стандартное действие с двумя исходами: «Одобрен» / «Отклонён». Не подходит, когда нужен третий вариант «Доработать» |
| **Действие «Запрос дополнительной информации»** | Гибкое действие, позволяющее задать произвольные поля (в т.ч. список вариантов) и получить ответ от участника процесса |
| **Поле типа «Список»** | Тип поля в настройке действия «Запрос дополнительной информации»; позволяет задать конечный набор вариантов для выбора |
| **Ветка условия** | Одно из направлений выполнения БП после проверки условия (аналог `if / else if / else`) |
| **Переменная БП** | Хранимое значение внутри шаблона, доступное для чтения и сравнения в условиях |
| **Статус** | Состояние документа в рамках БП «Со статусами»; переходы между статусами управляются логикой условий |

---

## Зачем заменять «Утверждение документа» на «Запрос дополнительной информации»

Действие **«Утверждение документа»** поддерживает ровно два исхода:
- Одобрен
- Отклонён

Когда бизнес-логика требует **трёх вариантов** (одобрить / отклонить / отправить на доработку), это действие становится недостаточным. Решение — использовать действие **«Запрос дополнительной информации»**, в котором можно вручную сформировать список вариантов любой длины.

> **Ключевой принцип:** Если нужно больше двух исходов для руководителя — всегда использовать «Запрос дополнительной информации» вместо «Утверждения документа».

---

## Настройка действия «Запрос дополнительной информации»

### Что нужно сделать:

1. **Удалить** (или заменить) действие «Утверждение документа» в статусе согласования у руководителя.
2. **Добавить** действие **«Запрос дополнительной информации»**.
3. В настройках действия:
   - Поле **«Комментарий»** — не использовать (оставить пустым или убрать).
   - Добавить **новое поле**:
     - **Тип поля:** `Список`
     - **Название поля:** например, `Что сделать?`
     - **Варианты списка:**
       - `Одобрить`
       - `Отклонить`
       - `Доработать`
4. **Сохранить** настройки действия.

> Порядок вариантов в списке влияет на удобство работы руководителя — рекомендуется ставить наиболее частый вариант первым.

## Построение логики ветвления (условия)

После того как руководитель выбирает вариант, значение сохраняется в переменную. Далее строится цепочка условий:

### Структура условий:

```
[Запрос доп. информации] → Что сделать?
        │
        ├── Равно "Одобрить"    → [Ветка одобрения]   → Запись в отчёт "Одобрено"
        │
        ├── Равно "Доработать"  → [Ветка доработки]   → Возврат на доработку
        │
        └── (иначе)             → [Ветка отклонения]  → Переход в финальный статус "Отклонена"
```

### Настройка каждого условия:

**Ветка «Одобрить»:**
- Тип: `Значение переменной`
- Переменная: поле ответа из «Запроса дополнительной информации» (`Что сделать?`)
- Оператор: `Равно`
- Значение: `Одобрить`
- Действия в ветке: те же, что были в предыдущей реализации одобрения + запись в отчёт «Одобрено»

**Ветка «Доработать»:**
- Тип: `Значение переменной`
- Переменная: то же поле
- Оператор: `Равно`
- Значение: `Доработать`
- Действия в ветке: отправка уведомления инициатору, возврат в статус доработки

**Ветка «Отклонить» (ветка по умолчанию / `else`):**
- Отдельное условие **не настраивается** — используется ветка `else` (иначе)
- Логика: если не «Одобрить» И не «Доработать» — значит, руководитель выбрал «Отклонить»
- Действия в ветке: переход документа в финальный статус «Отклонена»

> **Важно:** Третье условие (`else`) настраивать отдельно не нужно — оно охватывает все оставшиеся случаи. Это упрощает схему и снижает риск ошибок при изменении вариантов списка.

---

## Перенос существующих блоков между ветками

При перестройке логики важно **перетащить** (переместить) ранее настроенные действия в нужные ветки, а не создавать их заново:

1. Найти блок действий в старой ветке (например, запись в отчёт «Одобрено»).
2. Перетащить его в новую ветку «Одобрить» дизайнера БП.
3. Аналогично — действие возврата на доработку перенести в ветку «Доработать».

Это экономит время и сохраняет уже настроенные параметры действий.

---

## Проверка работы

После сохранения шаблона нужно **запустить тестовый экземпляр** БП:

1. Открыть документ и запустить БП.
2. Войти под учётной записью руководителя.
3. В задаче согласования появится поле **«Что сделать?»** с тремя вариантами.
4. Выбрать вариант **«Отклонить»** — проверить новую ветку.
5. Убедиться, что документ **сразу перешёл в финальный статус** «Отклонена», минуя этапы доработки.

**Ожидаемый результат:** После выбора «Отклонить» заявка немедленно переходит в последний статус без промежуточных шагов.

## Пошаговые инструкции

### Замена «Утверждения документа» на «Запрос дополнительной информации»

1. Открыть **шаблон БП** → нужный статус (согласование у руководителя).
2. Найти действие **«Утверждение документа»** и удалить его.
3. Добавить действие **«Запрос дополнительной информации»**.
4. В настройках действия нажать **«Добавить поле»**.
5. Выбрать тип поля — **«Список»**.
6. Ввести варианты: `Одобрить`, `Отклонить`, `Доработать`.
7. Нажать **«Сохранить»**.

### Настройка условий ветвления

1. После действия «Запрос» добавить блок **«Условие»**.
2. В первой ветке задать: `[поле ответа] = "Одобрить"`.
3. Перенести в эту ветку все действия одобрения + запись в отчёт.
4. Добавить вторую ветку с условием: `[поле ответа] = "Доработать"`.
5. Перенести в неё действие возврата на доработку.
6. Ветку **`else`** оставить для отклонения — добавить переход в финальный статус.
7. Сохранить шаблон и запустить тест.

## Главное

1. **«Утверждение документа» — только для двух исходов.** Как только нужен третий вариант — используй «Запрос дополнительной информации» с полем типа «Список».
2. **Поле типа «Список»** позволяет задать любое количество вариантов ответа, не ограничиваясь «Да / Нет».
3. **Ветка `else` не требует отдельного условия** — она автоматически перехватывает все случаи, не попавшие в явные условия. Это упрощает схему и делает её устойчивее к изменениям.
4. **Существующие блоки действий можно перетаскивать** между ветками — не нужно пересоздавать и перенастраивать их заново.
5. **Тестирование обязательно** — после каждого изменения структуры условий запускай тестовый экземпляр и проверяй каждую ветку вручную.
6. **БП «Со статусами» гибче «Последовательного»** именно за счёт возможности возвращаться в предыдущие статусы (доработка) или сразу завершать процесс (отклонение).
7. **Вариант «Отклонить» через `else`** означает: если руководитель намеренно выбрал «Отклонить», документ завершает процесс немедленно, без права на доработку — это принципиально отличает его от «Доработать».
